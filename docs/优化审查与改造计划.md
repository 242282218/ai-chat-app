# 优化审查与改造计划

## 问题审查

- Provider：已有 OpenAI / OpenAI-compatible 抽象，但 `newapi`、`sub2api`、`custom` 没有作为可选预设暴露。
- 图片生成：已有 `/images/generations` 调用，但根 Base URL 需要统一补齐 `/v1`，否则 `https://zzshu.cc` 会生成错误路径。
- CI：Android workflow 已跑 test / lint / build，但普通 CI 缺少 APK 和 mapping artifact；Gateway 缺少测试日志 artifact。
- 包体：release 已开启混淆，但资源压缩未开启。
- UI/UX：项目已有 Material 3 主题和共享工作台组件，后续应继续集中到统一 token 与共享组件，避免页面各自堆样式。
- 安全：API Key 不应进入代码、文档或备份；只允许通过 App 本地安全存储、环境变量或 GitHub Secrets 注入。

## 改造计划

1. Provider 统一适配层
   - 增加 `newapi`、`sub2api`、`custom` Provider 类型。
   - 三者复用 OpenAI-compatible Chat Completions 协议。
   - 聊天、模型发现、图片生成共用 Base URL 规范化。

2. 图片生成
   - Base URL 从 Provider 配置读取。
   - OpenAI 兼容类型自动补齐 `/v1`。
   - 保证图片生成路径为 `/v1/images/generations`。

3. 体积与构建
   - release 开启 `isMinifyEnabled` 和 `isShrinkResources`。
   - CI 上传 APK、mapping、lint 和测试报告。
   - 当前保留 `material-icons-extended`，因为多个页面已经依赖其中图标；后续逐步替换非必要图标，减少 Compose 图标依赖体积。

4. UI/UX
   - 延续 Material 3 原生组件、8dp 以内圆角、克制色彩和状态反馈。
   - 设计系统集中在 `ui/theme` 与 `ui/component`，页面只组合状态和业务。
   - 后续优先优化聊天主屏的重复 recomposition 和长列表扫视效率。

5. 测试
   - Provider 注册、类型展示、模型发现 URL、聊天 URL、图片 URL 都补单元测试。
   - CI 作为主要验证入口，本地只做开发过程中的最小回归。

## 当前完成项

- `newapi`、`sub2api`、`custom` 已纳入 Provider 类型和注册表。
- OpenAI 兼容 Provider 的根 Base URL 会自动补 `/v1`。
- 图片生成会请求 `/v1/images/generations`。
- Android CI 上传 build artifacts；Gateway CI 上传测试日志。
- `.env.example` 和 Provider 配置示例已补齐，且不包含真实 API Key。
