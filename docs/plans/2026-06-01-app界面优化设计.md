# App UI 优化设计方案：Calm Workbench

> 日期：2026-06-01  
> 范围：Android Kotlin Compose 全 App 信息架构与视觉系统  
> 结论：采用「方案 B：全 App 信息架构重排 + 视觉系统统一」  
> 参考约束：严格遵循 `D:\PROJECT_ZZZZZZZZZ\设计美学研究` 中 Claude 温暖知识感、OpenAI 白底生产力感、色彩纪律、排版纪律、交互纪律、状态覆盖和动效纪律。

## 1. 背景与问题定义

当前 App 已经具备 AI 聊天工作台的主要能力：聊天、Provider、Prompt、图片生成、Tools、数据备份和隐私设置。但界面组织仍偏「功能集合」而非「任务工作台」。用户反馈的「界面太满、入口太简陋」不是单个组件样式问题，而是信息架构和渐进披露策略不足。

基于当前代码审查，主要问题如下：

| 问题 | 当前表现 | 影响 |
|---|---|---|
| 首页入口像功能清单 | `HomeScreen` 先展示 hero、trust、搜索，再逐行列出 `Chat / Providers / Prompts / Images / Tools / Settings` | 用户打开 App 后需要自己判断从哪里开始，主任务入口不够强 |
| Chat 首屏过满 | `ChatScreen` 常驻 `ConversationStrip`、`ProviderStrip`、`ChatSettingsPanel`、`PromptPresetStrip`、消息列表、工具确认、错误、输入栏 | 主任务「阅读与回复」被配置控件挤压，认知负担高 |
| 管理页都从表单开始 | Provider、Prompt、Tools、Settings 多数页面直接展示完整配置表单或多个面板 | 新手压力大；高频动作和低频维护动作未分层 |
| 视觉 token 偏默认 Material 蓝 | `Theme.kt` 使用偏冷蓝主色 `#2454D6`，背景为冷灰 `#F7F8FA` | 与 Claude / OpenAI 参考中的温暖、克制、内容优先不一致 |
| Panel 过度复用 | `WorkbenchPanel` 被用于几乎所有信息块 | 所有区域视觉权重接近，缺少页面节奏 |
| 状态虽存在但缺少分阶段表达 | 多处有 `StatusPill`，但 AI 生成、图片生成、工具调用等长任务仍可更明确 | 用户难以理解当前阶段和失败恢复路径 |

### 1.1 真正要解决的问题

不是「把界面做得更漂亮」，而是：

1. 让用户打开 App 后立即知道可以做什么。
2. 让 Chat 页面默认只服务当前对话，不被配置项占满。
3. 让低频配置进入明确的管理区或可展开控制层。
4. 用一致的视觉系统表达可信、安静、内容优先的 AI 工作台。
5. 为后续实现提供可验证的设计约束，而不是泛泛的审美描述。

### 1.2 成功标准

- 首页首屏提供明确的「开始任务」入口，而不是只展示功能导航。
- Chat 默认状态下只保留：上下文状态、消息画布、输入栏。
- Provider / Prompt / Tools / 参数等控制项默认收起，但入口可发现。
- 全 App 使用同一套 light / dark semantic token。
- 主 accent 面积控制在 5%-10%，中性色承担 70%-90% 画面面积。
- AI 相关长任务覆盖 queued / thinking / streaming / done / failed / cancelled / retry。
- 所有主要页面有 empty、loading、error、success 和 recovery 设计。

## 2. 设计依据

本方案优先采用本地设计美学研究中的稳定规则，而不是照搬外部品牌。

### 2.1 Claude 温暖知识感

来源：`设计美学研究/packages/web-design-knowledge/design-systems/claude/DESIGN.md`

可执行规则：

- 核心气质：温暖、安静、理性、编辑感、可信。
- 页面主角是观点、产品输出和可信证据，不是抽象 AI 装饰。
- 使用暖纸色画布、暖黑文字、小面积赤陶强调。
- 组件低噪声：轻边框、弱阴影、surface 层级，不靠重阴影和玻璃拟态。
- Accent 面积控制在 5%-10%。
- Empty、Loading、Error 文案必须说明原因和下一步。

### 2.2 OpenAI / Codex 工作台生产力感

来源：`设计美学研究/packages/web-design-knowledge/design-systems/openai-productivity/DESIGN.md`

可执行规则：

- 核心气质：清晰、可信、内容优先、工作台感、低装饰。
- 首屏必须展示输入框、生成输出、编辑器、任务历史或工作区界面中的一种。
- 可信来自产品输出和内容结构，不来自未来主义装饰。
- 输出区域、对话区域和任务历史应成为主角。
- 状态覆盖 queued、thinking、streaming、done、failed、empty。

### 2.3 Claude 页面节奏

来源：`references/claude-design-research/page-rhythm.md`

可执行规则：

```text
主张
→ 解释
→ 示例
→ 进一步细分
→ 信任 / 边界
→ CTA
```

在 App 内转化为：

```text
当前任务
→ 当前上下文
→ 当前输入 / 输出
→ 可选控制
→ 风险 / 状态
→ 下一步动作
```

### 2.4 必须规避的反模式

来源：`references/claude-design-research/anti-patterns.md`、`craft/color.md`

本 App 禁止：

- 蓝紫科技渐变。
- neon 色、发光球、神经网络、大脑、机器人装饰。
- 纯白大画布 + 黑粗体标题冒充 Claude 风格。
- 所有区域都是重复卡片网格。
- CTA 太多、状态色到处抢视觉权重。
- 低对比灰字制造“高级感”。
- loading 只有 spinner，没有阶段说明。

## 3. 总体设计方向：Calm Workbench

推荐方向命名为 **Calm Workbench**：温暖、克制、任务优先的本地 AI 工作台。

设计目标不是变成 Claude App 的复制品，也不是变成 Codex 的桌面 IDE，而是在 Android 原生 Material 3 基础上，吸收两者的信息组织方式：

- Claude：安静、温暖、编辑式层级。
- Codex / OpenAI：任务输入优先、工作区优先、配置项退后。
- 当前 App：本地优先、BYOK、多 Provider、Tools、图片、备份隐私。

### 3.1 设计原则

#### 原则 1：任务入口高于功能入口

首页不应先问用户「你要进入哪个功能页面」，而应先提供可执行任务：

- 直接提问。
- 继续最近对话。
- 开始临时聊天。
- 生成图片。
- 搜索历史。

功能管理入口仍保留，但降级为状态卡或底部管理区。

#### 原则 2：沉浸工作区高于配置面板

Chat 默认界面只保留当前对话必要元素：

- 当前会话标题。
- 当前模型 / Provider 简要状态。
- 消息画布。
- 输入栏。

会话列表、模型参数、Prompt、Tools、清空上下文等进入 control sheet 或折叠区。

#### 原则 3：渐进披露，不隐藏能力

低频能力不删除，而是按照使用频率分层：

| 层级 | 内容 | 展示方式 |
|---|---|---|
| L1 高频 | 输入、发送、停止、继续最近对话 | 常驻 |
| L2 中频 | 切换模型、选择 Prompt、开关 Tools、临时聊天 | context bar / bottom sheet |
| L3 低频 | Provider 编辑、Gateway 配置、备份导入导出 | 管理页 |
| L4 高风险 | 删除、清空、导入覆盖、工具执行 | 明确确认 + 恢复说明 |

#### 原则 4：状态必须解释下一步

状态不是装饰 pill。每个状态必须说明：

```text
现在发生什么
为什么这样
用户下一步能做什么
```

例如：

- `需要 Provider`：说明聊天不可用，并提供「配置 Provider」动作。
- `Tools 未连接`：说明工具不会参与回答，并提供「连接 Gateway」动作。
- `生成失败`：说明失败原因、影响范围，并提供 retry / edit input。

#### 原则 5：视觉克制，内容做主角

- 中性色承担大面积。
- Accent 只用于主 CTA、链接、当前状态和少量高价值强调。
- 不用大面积渐变、不用炫技动效。
- 用真实对话、生成结果、工具输出、最近历史作为视觉证据。

## 4. 新信息架构

### 4.1 全 App 结构

```text
Home 任务启动台
├─ Task Composer：直接输入并开始聊天
├─ Quick Actions：新聊天 / 临时聊天 / 图片生成 / 搜索历史
├─ Continue：最近对话、最近图片、最近工具结果
├─ System Status：Provider、Tools、隐私状态
└─ Manage：Providers / Prompts / Tools / Settings

Chat 沉浸对话工作区
├─ Context Bar：会话、模型、工具、上下文状态
├─ Message Canvas：消息、图片、工具结果、状态
├─ Composer：文本、图片、发送、停止、编辑状态
└─ Control Sheet：会话列表、Provider、参数、Prompt、Tools、危险操作

Images 图片创作工作区
├─ Image Composer：Prompt、主 CTA
├─ Compact Controls：Provider、Model、尺寸、质量、数量
├─ Generation Status：queued / generating / done / failed / cancelled
└─ Gallery：历史、复用、保存、分享

Providers 管理页
├─ Health Summary：可用 Provider、默认模型、风险提示
├─ Provider List：状态优先
└─ Edit Sheet：新增 / 编辑 Provider

Prompts 管理页
├─ Search + Category：搜索和分类
├─ Prompt Cards：摘要优先
└─ Edit Sheet：新增 / 编辑 Prompt

Tools 管理页
├─ Gateway Status：连接状态、权限摘要
├─ Tool Catalog：工具能力列表
├─ Test Workbench：搜索 / Sandbox 测试区
└─ Permission Policy：确认策略、历史记录

Settings 数据与隐私页
├─ Privacy Summary：本地数据、API Key、备份范围
├─ Backup：导出 / 导入 / 预览
├─ Sensitive Data：敏感会话、临时会话说明
└─ Diagnostics：状态、日志、版本信息
```

### 4.2 导航策略

当前 `AppDestination.topLevel` 包含 Chat、Providers、Prompts、Images、Tools、Settings。后续保留这些 route，但调整入口权重：

| Destination | 新定位 | 首页展示方式 |
|---|---|---|
| Chat | 核心工作区 | Composer 提交后进入；也有「新聊天」快捷动作 |
| Images | 创作工作区 | Quick Action |
| Providers | 模型连接管理 | System Status 卡 + Manage 区 |
| Prompts | 任务模板管理 | Control Sheet 引用 + Manage 区 |
| Tools | Gateway / 工具管理 | System Status 卡 + Manage 区 |
| Settings | 数据隐私管理 | Privacy Status 卡 + Manage 区 |

## 5. 视觉系统

### 5.1 色彩方向

推荐主方向：**Claude Warm + OpenAI Productivity**。

理由：

- 当前是 AI Chat / 知识工作台，Claude 温暖知识感更符合可信和长时间阅读。

### 5.5 排版

Android Compose 默认字体可继续使用系统 sans，避免引入复杂字体依赖。通过字号、字重、行高建立层级。

建议层级：

| 层级 | 用途 | 建议 |
|---|---|---|
| Display / Hero | 首页任务启动标题 | 32-36sp，weight 400-500 |
| Title Large | 页面标题 / 主要分区 | 22-26sp，weight 500 |
| Title Medium | 卡片标题 | 16-18sp，weight 500-600 |
| Body | 对话、说明、表单 | 15-17sp，line height 1.5 左右 |
| Label | pill、元信息 | 11-13sp，weight 500 |
| Mono | API URL、header、JSON、tool output | 13-14sp monospace |

约束：

- 中文正文不得低于 15sp。
- 标题不要全部 700+，避免粗暴层级。
- 长文本行宽在手机端自然受限；平板 / 横屏需要限制 message bubble 最大宽度。
- Mono 只用于代码、URL、JSON、状态 ID，不用于普通说明。

### 5.6 Shape、Border、Elevation

| 元素 | 建议 |
|---|---|
| 小控件 | 8dp radius |
| 输入框 / 小卡片 | 10-12dp radius |
| Composer / bottom sheet / hero | 14-18dp radius |
| 边框 | 1dp hairline，低透明度 |
| 阴影 | 默认不用重阴影；sheet / dialog 使用弱 elevation |
| 卡片 hover | Android 无 hover 主路径，按 press / selected / focus 表达 |

## 6. 核心页面设计

## 6.1 Home：任务启动台

### 当前问题

`HomeScreen.kt` 当前结构是：

```text
TopAppBar
WorkbenchHero
TrustStrip
ConversationSearchPanel
SectionHeader("工作台")
DestinationRow x 6
```

问题是入口仍是页面跳转列表，用户需要先理解功能分类，再开始任务。

### 目标结构

```text
Top app bar: AI Chat Workbench + status affordance
TaskComposerHero
QuickActionGrid
ContinueSection
SystemStatusStrip
ManagementSection
```

### 关键组件

#### TaskComposerHero

替代当前 `WorkbenchHero` 的首屏主角。

内容：

- Eyebrow：`本地优先 · BYOK`
- 标题：`今天想让 AI 帮你做什么？`
- 大输入框 placeholder：`输入问题、粘贴材料，或描述要完成的任务`
- 主按钮：`开始聊天`
- 次按钮：`临时聊天`
- 状态提示：如果没有 Provider，输入框保留但主按钮变为 `配置 Provider 后开始`。

状态：

| 状态 | 表现 |
|---|---|
| ready | 可输入，主 CTA 可用 |
| no-provider | CTA 指向 Provider 设置，说明请求会直接发送到配置 endpoint |
| draft-empty | CTA disabled，并说明需要输入内容 |
| starting | CTA loading，文案 `创建对话...` |
| failed | 保留草稿，显示原因与重试 |

#### QuickActionGrid

最多 4 个动作，避免功能堆叠：

1. 新聊天
2. 临时聊天
3. 图片生成
4. 搜索历史

Provider、Prompts、Tools、Settings 不在 Quick Action 中抢主入口，它们放到系统状态和管理区。

#### ContinueSection

优先展示最近可继续对象：

- 最近 3 条对话。
- 最近 1-2 个图片生成结果。
- 最近工具调用结果可后置。

没有历史时，不展示空卡片堆叠，改为温和 empty：

```text
还没有可以继续的任务。
先输入一个问题，或创建临时聊天。
```

#### SystemStatusStrip

三个小状态：

- Provider：`已连接 / 需要配置`
- Tools：`Gateway 可用 / 未启用`
- Privacy：`本地保存 / 临时聊天可用`

点击进入对应管理页。

### 首页验收

- 首屏必须出现可输入的任务入口。
- 管理入口不超过首屏视觉权重的 25%。
- Quick actions 不超过 4 个。
- 无 Provider 状态必须提供明确下一步。
- 最近任务为空时不得展示大面积空白或重复卡片。

## 6.2 Chat：沉浸对话工作区

### 当前问题

`ChatScreen.kt` 当前常驻结构：

```text
TopAppBar actions: 新建、临时、归档、删除
ConversationStrip
ProviderStrip
NoProviderPanel
ChatSettingsPanel
PromptPresetStrip
MessageList
ToolCallConfirmationPanel
ChatErrorPanel
InputBar
```

这导致配置层、会话层、消息层、输入层同时争夺注意力。

### 目标结构

默认视图：

```text
ConversationContextBar
MessageCanvas
InlineStateArea
ChatComposer
```

展开控制：

```text
ChatControlSheet
├─ Conversations
├─ Provider / Model
├─ Parameters
├─ Prompt preset
├─ Tools
└─ Danger zone
```

### ConversationContextBar

替代 TopAppBar 上大量 icon actions + 常驻 strip。

显示：

- 当前会话标题。
- 临时 / 敏感 / 消息数量状态。
- 当前 Provider / Model 简写。
- Tools 状态。
- 一个 `Controls` 按钮打开 sheet。

示例：

```text
[返回] 需求讨论       临时 · 24 条 · OpenAI / gpt-4.1  [Controls]
```

### MessageCanvas

消息画布是 Chat 的主角。

布局规则：

- User 消息靠右或与 assistant 形成明确差异，但避免高饱和整块蓝。
- Assistant 消息使用 `surface` 或透明背景，内容优先。
- Tool 消息使用 `surfaceSunken`，默认摘要，支持展开 stdout / stderr / search sources。
- System / Context summary 使用低权重，不干扰主阅读。

消息状态：

| 状态 | 表现 |
|---|---|
| sending | 用户消息旁小状态 |
| thinking | assistant 占位，显示具体阶段，例如 `整理上下文...` |
| streaming | 文本流式出现，顶部或消息尾部显示 `生成中` |
| done | 显示复制、重试、编辑等操作 |
| failed | 在消息位置显示失败原因、影响、重试 |
| cancelled | 保留已生成内容，提示 `已停止，可继续重试` |

### ChatComposer

输入栏设计为底部稳定工作区：

- 多行输入。
- 图片草稿横向预览。
- 主按钮：发送 / 停止。
- 次级按钮：添加图片、工具 / prompt 快捷入口。
- 编辑状态时显示 `正在编辑上一条消息`，并提供取消。

约束：

- 输入区不应被参数设置挤占。
- 发送按钮 disabled 时必须说明原因：无 Provider、空输入、生成中等。
- 生成超过 1s 需要阶段文案。
- 生成超过 10s 必须可停止。

### ChatControlSheet

把当前常驻控制项迁入 bottom sheet 或 modal sheet。

分区：

1. 会话
   - 最近会话 chips / list。
   - 新建对话。
   - 临时聊天。
2. 模型
   - Provider 切换。
   - Model。
   - Provider 未配置时 CTA。
3. 参数
   - temperature、max tokens、top p 等。
   - 默认折叠，只展示摘要。
4. Prompt
   - 选择 Prompt 预设。
   - 当前 system prompt 摘要。
5. Tools
   - 启用 / 禁用。
   - 权限摘要。
6. Danger zone
   - 清空上下文。
   - 归档。
   - 删除。

危险操作必须保留确认对话，不放在默认视图的 top bar 中。

### No Provider 状态

不要在 Chat 中占用大块常驻面板。改为：

- Context bar 显示 `需要 Provider`。
- Message canvas 中显示轻量 empty：

```text
还不能发送消息。
添加 OpenAI 或兼容 Provider 后，请求会从本机直接发送到你的 endpoint。
[配置 Provider]
```

### Chat 验收

- 默认首屏不展示完整 ProviderStrip / ChatSettingsPanel / PromptPresetStrip。
- 消息列表高度显著增加，成为页面主区域。
- 所有配置项可通过一个清晰入口到达。
- 停止、重试、编辑、复制仍可发现。
- Tool 调用确认保留在上下文附近，不弹出无来源的孤立提示。

## 6.3 Images：图片创作工作区

### 当前问题

`ImageGenerationScreen.kt` 当前表单中 Provider、Prompt、Model、Size、Quality、Count 同时常驻，历史列表在下方。对于高频使用，Prompt 和结果才是主角，参数应折叠。

### 目标结构

```text
ImageComposerCard
CompactGenerationControls
GenerationStatus
Gallery
```

### ImageComposerCard

主角是 Prompt：

- 大 prompt 输入框。
- 生成按钮。
- 当前 Provider / Model 摘要。
- 参数摘要：`1024x1024 · standard · 1 张`。

### CompactGenerationControls

尺寸、质量、数量、Provider、Model 默认折叠。展开后编辑。

建议使用：

- Segmented chips：尺寸。
- Chips：质量。
- Stepper 或小输入：数量。
- Provider picker：只展示支持图片生成的 provider。

### Gallery

历史从「列表」升级为更像结果画廊：

- 最近结果优先大图。
- 每张图显示 prompt 摘要、时间、model、状态。
- 操作：复用 Prompt、重新生成、保存、分享。

### 状态

| 状态 | 表现 |
|---|---|
| empty | 展示 prompt 示例和参数说明 |

`ProviderSettingsScreen.kt` 顶部直接展示完整 Provider 表单，然后才是已配置列表。对已有 provider 的用户来说，默认看到的是低频编辑区。

### ProviderHealthHeader

展示：

- 默认 Provider / Model。
- API Key 是否以加密引用保存。
- 是否存在 HTTP endpoint / custom headers 风险。

### ProviderList

每个 Provider row 展示：

- 类型。

### 当前问题

`DataSettingsScreen.kt` 当前直接展示导出、导入、清空等高风险操作。备份 JSON 文本框占据大量空间，隐私信息没有先给摘要。

### PrivacySummaryHeader

优先说明：

## 7. 组件系统改造

### 7.1 组件分层

当前 `WorkbenchPanel` 承担过多职责。建议拆成更明确的组件族。

| 组件 | 用途 | 替代 / 关系 |
|---|---|---|
| `TaskComposerHero` | 首页主任务入口 | 替代首页 `WorkbenchHero` |
| `SectionSurface` | 普通分区容器 | 收敛 `WorkbenchPanel` 的默认使用 |
| `StatusSummaryCard` | 系统状态摘要 | 首页 Provider / Tools / Privacy |
| `ActionCard` | 快捷动作入口 | 替代部分 `DestinationRow` |
| `ManagementRow` | 管理页入口 | 替代低频 destination row |
| `ContextBar` | Chat 当前上下文 | 替代 ConversationStrip + ProviderStrip 摘要 |
| `ControlSheet` | Chat / Images 参数控制 | 收纳低频配置 |
| `ResultPanel` | AI 输出、Tool 输出、图片结果 | 强化真实输出证据 |
| `DangerZone` | 高风险操作分组 | Settings / Chat / Provider 删除类操作 |

### 7.2 WorkbenchPanel 使用约束

保留 `WorkbenchPanel`，但降低滥用：

- 不再每个小区域都包 panel。
- 一个页面首屏最多 1 个高权重 panel。
- 同级 panel 不超过 3 个连续堆叠。
- 表单和结果不要混在同一 panel 中。

### 7.3 StatusPill 语义

当前 `StatusTone` 可保留，但需要统一语义。

| Tone | 用途 | 禁止用途 |
|---|---|---|
| Neutral | 信息、数量、普通标签 | 表达成功或警告 |
| Accent | 当前选择、生成中、主状态 | 大面积装饰 |
| Success | 可用、已连接、已保存 | 增长、营销强调 |
| Warning | 需配置、能力受限、HTTP 风险 | 普通提示 |
| Critical | 错误、危险、删除 | 非错误状态 |

### 7.4 输入组件

- 高价值输入使用大输入区，例如 Home task composer、Chat composer、Image prompt。
- 管理表单使用分组，减少首屏字段数量。
- Advanced 字段默认折叠。
- 表单 disabled 必须说明解锁条件。

## 8. 交互与状态设计

依据：`craft/interaction-discipline.md`、`craft/state-coverage.md`、`craft/animation-discipline.md`。

### 8.1 反馈时间

| 时间 | 要求 |
|---:|---|
| 100ms 内 | pressed / selected / focus / loading 反馈 |
| 300ms 后 | 显示 loading 或状态变化 |
| 1s 后 | 显示阶段文案 |
| 10s 后 | 允许取消、离开或后台处理 |
| 60s 后 | 升级为明确进度、通知或错误恢复 |

### 8.2 AI Chat 状态

| 状态 | 文案示例 | 可用动作 |
|---|---|---|
| queued | `等待发送...` | 取消 |
| thinking | `整理上下文...` / `等待 Provider 响应...` | 停止 |
| streaming | `正在生成...` | 停止、复制已生成内容 |
| needs-input | `需要确认 Tool 调用` | 确认 / 拒绝 |
| done | `已完成` | 复制、重试、编辑 |
| failed | `请求失败：认证无效` | 修改 Provider、重试 |
| cancelled | `已停止，保留已生成内容` | 继续 / 重试 |

### 8.3 Tool 状态

| 状态 | 要求 |
|---|---|
| manifest loading | 显示正在读取 Gateway tools |
| unavailable | 说明 Gateway 未开启或地址不可用 |
| permission required | 显示工具名、参数摘要、权限级别、风险 |
| running | 显示具体工具阶段 |
| done | 显示结构化结果和来源 |
| failed | 显示错误 code、message、retry |

### 8.4 图片生成状态

| 状态 | 要求 |
|---|---|
| ready | Prompt 和 Provider 就绪 |
| invalid | 说明缺失 Prompt / Provider / Model 不支持 |
| generating | 阶段文案，不只按钮显示生成中 |
| done | 图片进入 gallery，说明本地保存位置 |
| failed | 保留 prompt 和参数，可重试 |

### 8.5 动效约束

- 普通 pressed / selected：50-100ms。
- Sheet / dialog：200-300ms。
- 页面切换：300-500ms。
- 普通内容入场位移 8-20dp 内。
- 禁止强滚动编舞、发光、视差和大面积模糊。
- 尊重系统 reduced motion；Android 实现阶段应尽量避免不可关闭的循环动画。

## 9. 响应式与设备适配

虽然当前是 Android App，但仍需考虑不同宽度。

### 9.1 手机竖屏

- 单列布局。
- 20dp 左右 gutter。
- Chat 输入栏底部固定。
- Control sheet 从底部出现。
- Touch target 不小于 44dp。

### 9.2 手机横屏 / 折叠屏 / 平板

## 11. 验证方式

### 11.1 静态检查

- 检查新增颜色是否符合中性色 70%-90%、accent 5%-10%。
- 检查是否引入蓝紫科技渐变、neon、重阴影、玻璃拟态。
- 检查页面是否出现 4 个以上连续同权重 panel。
- 检查默认 Chat 是否仍常驻多个配置面板。

### 11.3 手工验收清单

#### Home

- 新装 App，无 Provider，首页能明确引导配置。
- 配置 Provider 后，首页输入问题能进入 Chat。

- 不做大型动效和滚动编舞。
- 不引入非必要字体依赖。
- 不把 Claude / OpenAI 品牌视觉直接复制到 App。
- 不为了视觉改版改变 Provider、Gateway、Room 的核心业务行为。

## 13. 最小可交付切片

如果需要先做一个高价值版本，推荐顺序：

1. `Theme.kt` 调整为 Calm Workbench token。
2. 首页改为 Task Composer + Quick Actions + System Status。
3. Chat 增加 ContextBar，并把 Provider / 参数 / Prompt 收到 Control Sheet。
4. Provider 和 Prompt 页面把表单迁入 sheet，默认展示列表和摘要。
5. Settings 把 JSON 原文折叠，并增加 Privacy Summary / Danger Zone。

这个切片可以直接验证两件事：

- 入口是否不再简陋。
- Chat 是否不再拥挤。

## 14. 设计评审清单

交付前按以下五维检查，来自本地设计知识库的质量语言：

| 维度 | 检查问题 |
|---|---|
| Philosophy | 是否任务优先，而不是功能堆叠？ |
| Hierarchy | 用户一眼能否分辨主任务、状态、低频设置？ |
| Execution | token、组件、状态、动效是否可落地到 Compose？ |
| Specificity | 文案是否说明原因、影响、下一步，而不是泛泛提示？ |
| Restraint | 是否克制使用 accent、卡片、阴影和动效？ |

最低要求：

- 总分至少 18/25。
- 单项不得低于 3。
- P0 反模式不得出现。

## 15. 结论

本次改版应按「全 App 信息架构重排 + 视觉系统统一」推进，而不是只换颜色或单独美化首页。

推荐优先级：

```text
入口主路径
→ Chat 降噪
→ 管理页分层
→ 图片工作区化
→ 状态 / 动效 / 无障碍收尾
```

这样能以最小风险解决用户已感知的问题，同时保留当前 App 已经实现的 Provider、Prompt、Tools、图片和备份能力。最终效果应接近：

- Claude 的安静可信和编辑式节奏。
- Codex / OpenAI 的任务输入优先和工作台效率。
- Android 原生 Compose 的可访问、稳定、低维护实现。
