# AI 聊天软件需求文档

日期：2026-05-31
状态：已选择主方案
主方案：方案 A，原生 App + 可选工具网关

## 1. 背景

目标是开发一款安卓原生、轻量、流畅的 AI 聊天软件。它不只是 ChatGPT 壳子，而是一个本地优先的 AI 工作台：能聊天、生成图片、搜索新闻、做小规模代码验证，并能通过 OpenAI 与 OpenAI-compatible API 接入不同模型服务。

本需求参考了以下开源项目和官方资料：

- RikkaHub：安卓 AI 聊天客户端，支持多 Provider、MCP、搜索、Markdown、LaTeX、Mermaid、分支对话、记忆等能力。<https://github.com/rikkahub/rikkahub>
- GPT Mobile：Kotlin + Jetpack Compose 的移动 AI 聊天应用，强调原生 UI、本地历史、多模型并行。<https://github.com/Taewan-P/gpt_mobile>
- Chatbox：开源 AI 客户端，强调本地数据、流式回复、Prompt 管理、多平台体验。<https://github.com/chatboxai/chatbox>
- Open WebUI：开源 AI 平台，支持 Web Search、工具、RAG、图片生成等生产力能力。<https://docs.openwebui.com/features>
- LibreChat：开源 AI 聊天平台，支持 Agents、Tools、Code Interpreter、Image Generation、Web Search。<https://www.librechat.ai/docs/features>
- Android Jetpack Compose：Android 官方现代原生 UI 工具包。<https://developer.android.com/develop/ui>

## 2. 产品定位

产品定位为“安卓原生、本地优先、轻量可扩展的 AI 工作台”。

核心原则：

- 原生体验优先：主体验必须是 Android 原生，不使用 WebView 套壳作为主界面。
- 本地优先：聊天历史、模型配置、Prompt、图片记录默认保存在本机。
- 轻量优先：基础聊天、图片生成、模型配置不依赖自建后端。
- 多模型优先：支持 OpenAI 与 OpenAI-compatible API，后续可扩展更多 Provider。
- 工具化优先：搜索、代码验证、图片生成等能力通过统一 Tool 层组合。
- 安全优先：API Key、聊天记录、联网搜索、代码执行都必须有明确边界。

## 3. 已选方案

选择方案 A：原生 App + 可选工具网关。

该方案的定义：

- Android App 是主产品，负责 UI、聊天、模型配置、本地数据、图片生成入口和工具调用编排。
- 基础聊天直接从 App 请求用户配置的模型 Provider，不强制经过自建服务。
- 可选工具网关只处理高风险或需要服务端环境的能力，例如新闻搜索代理、代码沙箱、MCP 服务代理、团队级 Key 代理。
- 没有工具网关时，App 仍然必须能完成基础聊天、OpenAI-compatible API 配置、历史记录、Prompt 管理、图片生成。

选择该方案的原因：

- 能满足安卓原生流畅体验。
- 能保持轻量，不把普通聊天做成重型平台。
- 能把代码执行、搜索代理等高风险能力隔离到可控边界。
- 能为后续 MCP、搜索、代码执行、文件处理留出扩展空间。

明确不采用：

- 不采用 Web/PWA 套壳作为主线。
- 不直接 fork 某个开源项目作为主线，只参考能力和交互。
- 不自研大模型推理框架。
- 不在 App 本机裸跑不受控代码。

## 4. 目标用户

- 需要在手机上高频使用 AI 的个人用户。
- 需要接入自定义模型、代理服务或私有 OpenAI-compatible API 的进阶用户。
- 需要轻量完成写作、搜索、代码片段验证、图片生成等任务的生产力用户。

暂不面向企业后台管理、团队协作、复杂知识库运营等重型场景。

## 5. 成功指标

- 冷启动进入主界面时间小于 1.5 秒。
- 普通聊天首 token 延迟主要受模型服务影响，App 自身不引入明显阻塞。
- 长回复流式渲染不卡顿，聊天列表滚动稳定。
- 用户能在 1 分钟内完成 OpenAI-compatible API 配置并发起第一轮对话。
- 无工具网关时，基础聊天、模型配置、历史记录、本地 Prompt 可完整使用。
- 有工具网关时，搜索新闻和代码验证能稳定执行并返回可追踪结果。
- API Key 默认只保存在本机，并通过 Android Keystore 或等价机制保护。
- 普通日志不出现 API Key、完整请求头、完整隐私对话内容。

## 6. 范围

### 6.1 MVP 范围

- Android 原生 App。
- OpenAI Provider。
- OpenAI-compatible Provider。
- 文本聊天、流式回复、停止生成、失败重试。
- 本地历史记录、本地 Provider 配置、本地 Prompt。
- Markdown、代码块、表格、LaTeX 基础渲染。
- 图片生成。
- 可选工具网关接入。
- 新闻/网页搜索工具。
- 小规模代码验证工具。

### 6.2 二期范围

- MCP 工具接入。
- Provider 能力探测和模型能力缓存。
- 图片编辑、图生图。
- 对话分支、消息引用、长对话压缩。
- 文件上传、文档总结。
- 本地模型或局域网模型接入，例如 Ollama。
- 工具市场或工具配置中心。

### 6.3 暂不做

- 企业多租户后台。
- 团队知识库权限管理。
- 完整 IDE。
- 复杂 Agent 工作流编排器。
- 自研模型训练或推理框架。
- 在 Android 本机直接执行用户代码。

## 7. 功能需求

### 7.1 原生基础体验

- 使用 Kotlin + Jetpack Compose + Material 3。
- 主界面、聊天列表、输入框、设置页、图片预览、文件选择都必须为原生实现。
- 聊天列表需要支持长内容优化，避免大对话卡顿。
- 输入框支持多行输入、粘贴、清空、重新生成、停止生成。
- 支持深色模式、动态字体、系统返回手势。
- 网络请求、图片加载、Markdown 渲染不得阻塞主线程。
- 关键操作要有明确状态：发送中、生成中、取消中、失败、已完成。

### 7.2 聊天能力

- 支持创建、重命名、删除、归档对话。
- 支持消息编辑后重新发送。
- 支持失败重试、停止生成、复制消息。
- 支持系统提示词和会话级 Prompt。
- 支持模型参数配置：temperature、top_p、max_tokens 等。
- 支持对话内搜索。
- 支持临时对话，临时对话默认不写入长期历史。
- 支持按会话切换模型。
- 支持清理上下文后继续同一会话。

### 7.3 原生显示能力

- 支持 Markdown。
- 支持代码高亮。
- 支持表格。
- 支持 LaTeX。
- 支持 Mermaid 预览，MVP 可先支持静态预览或导出图片预览。
- 支持图片消息、图片生成结果、下载与分享。
- 支持工具调用过程折叠展示。
- 支持模型思考内容折叠展示，避免默认占满聊天界面。
- 支持引用来源展示，尤其是搜索新闻场景。
- 渲染失败时保留原始文本，不应让消息不可读。

### 7.4 模型与 Provider

- 内置 OpenAI Provider。
- 支持 OpenAI-compatible Provider。
- 用户可配置 Base URL、API Key、模型名、自定义 Header。
- Provider 不应硬编码在 UI 层，应通过统一接口适配。
- 模型能力以结构化方式描述：文本、视觉输入、图片生成、工具调用、联网搜索、结构化输出、长上下文。
- 支持模型收藏、默认模型、按会话切换模型。
- 支持 Provider 连通性测试。
- 支持请求超时、重试、取消。
- 支持流式与非流式响应，优先使用流式。
- 对 OpenAI-compatible API 的差异要做兼容降级，例如不支持工具调用时退回普通文本模式。

### 7.5 图片生成

- 支持文生图。
- 支持选择尺寸、质量、数量、风格或等价参数。
- 支持保存生成历史。
- 支持重新生成、复用提示词、下载、分享。
- 图片生成应复用 Provider 能力，不要求必须经过工具网关。
- 二期支持图生图和图片编辑。
- 图片接口优先复用 OpenAI 图片接口与 OpenAI-compatible 图片接口，不自研图片生成后端。
- 图片结果需要生成缩略图缓存，避免历史列表直接加载原图。

### 7.6 搜索新闻

- 搜索新闻通过 Tool 层调用，可由工具网关提供。
- 搜索结果必须包含标题、摘要、来源链接、发布时间或抓取时间。
- AI 回答中需要展示引用来源。
- 支持时间筛选，例如最近一天、最近一周。
- 搜索工具调用前应让用户知道会访问外部网络。
- 搜索失败时要返回可理解错误，不让模型编造结果。
- 搜索结果需要保留原始来源，便于用户点开核对。
- 需要区分“模型回答”和“搜索事实来源”，不能混成一个不可追踪文本块。

### 7.7 小规模代码验证

- 代码验证通过可选工具网关执行。
- MVP 优先支持 Python 或 JavaScript，至少先稳定支持一种语言。
- 必须在沙箱中执行，不能直接裸跑本机命令。
- 必须有超时限制、输出大小限制、资源限制。
- 输出应展示 stdout、stderr、退出状态、执行时长。
- 默认禁用危险能力，例如文件系统任意访问、无限网络访问、长时间后台任务。
- 代码执行工具调用前必须让用户确认。
- 代码执行结果必须作为工具结果回写到对话，不应伪装成模型直接回答。

### 7.8 工具与插件

- 设计统一 Tool 接口，用于搜索、代码执行、图片生成、时间、计算器等能力。
- 工具调用过程应可追踪、可展开、可复制结果。
- 工具权限需要分级：只读工具、联网工具、执行工具、高风险工具。
- 高风险工具默认需要用户确认。
- 工具调用失败时要把错误结构化返回给模型和 UI。
- 优先兼容 MCP，避免自研封闭插件协议。
- MVP 工具可以内置，二期再开放用户自定义工具。

### 7.9 本地数据

- 聊天记录默认保存在本地。
- Provider 配置默认保存在本地。
- Prompt、收藏、图片生成历史默认保存在本地。
- 支持导入导出配置和聊天记录。
- 支持一键清理本地数据。
- API Key 必须加密存储。
- 临时对话、敏感对话要能选择不入库或退出后删除。
- 本地数据结构应预留版本号，便于后续迁移。

### 7.10 生产力入口

首页不只提供普通聊天，还应提供轻量工作入口：

- 普通聊天。
- 写作润色。
- 代码验证。
- 新闻搜索。
- 图片生成。
- 文档总结，二期支持。

这些入口本质上是预设 Prompt、默认模型和工具组合，不应做成互相割裂的独立产品。

## 8. 非功能需求

### 8.1 性能

- App 自身不应在聊天请求前做重计算。
- 长列表、长 Markdown、长代码块必须避免主线程阻塞。
- 图片生成历史需要缩略图缓存，避免直接加载原图导致卡顿。
- 网络请求必须支持取消。
- Provider 配置页和会话列表应本地秒开。
- 工具调用状态需要增量更新，避免等待全部完成后才展示。

### 8.2 轻量化

- 基础功能不依赖自建服务。
- 尽量减少后台常驻任务。
- 不引入重型跨平台 UI 框架。
- 三方库选择以成熟、维护活跃、体积可控为原则。
- 工具网关是可选能力，不能成为基础聊天的前置依赖。

### 8.3 隐私与安全

- 明确显示当前请求发送到哪个 Provider。
- API Key 不上传到非用户配置的服务。
- 日志不得明文记录 API Key、完整隐私内容。
- 搜索、代码执行、文件上传等高风险工具默认需要显式确认。
- 支持清空本地历史和配置。
- 工具网关不得默认保存用户完整对话。
- 如果工具网关需要缓存搜索或执行结果，必须有明确过期时间。

### 8.4 可维护性

- UI、Domain、Provider、Tool、Storage、Gateway Client 分层。
- 业务逻辑尽量纯函数化，副作用集中在边界层。
- 不为单次需求创建复杂抽象。
- 保持 Android 原生架构，避免把 Web 项目的状态模型照搬到 App。
- Provider 和 Tool 都要可以独立测试。

## 9. 方案 A 架构

### 9.1 总体结构

主架构为：

- Android App：主产品。
- Local Storage：本地数据库、配置、加密 Key 存储。
- Provider Layer：OpenAI、OpenAI-compatible、未来其他模型服务。
- Tool Layer：搜索、代码验证、图片生成、时间、计算器、MCP。
- Optional Gateway：可选工具网关，只处理需要服务端环境或隔离风险的能力。

### 9.2 Android App 模块

- UI 层：Compose 页面、聊天渲染、设置页、工具结果展示、图片预览。
- Domain 层：会话、消息、模型能力、工具调用、Prompt、生产力入口。
- Provider 层：统一模型请求接口、流式解析、错误归一化、能力声明。
- Tool 层：工具注册、工具权限、工具调用、工具结果格式化。
- Storage 层：本地数据库、配置、图片缓存、Key 加密存储。
- Gateway Client：工具网关鉴权、请求、超时、取消、错误处理。

### 9.3 可选工具网关职责

工具网关只做 App 不适合直接做的事：

- 搜索代理：统一接入搜索服务，隐藏搜索服务 Key。
- 代码沙箱：执行短代码，限制 CPU、内存、运行时间、网络和文件访问。
- MCP 代理：连接服务端 MCP 工具，向 App 暴露工具清单。
- 团队 Key 代理，二期可选：集中管理团队模型 Key，但不作为个人版默认能力。

工具网关不做：

- 不保存默认聊天历史。
- 不强制代理普通模型聊天。
- 不替代 App 的本地数据库。
- 不把所有 Provider 请求都劫持到服务端。

### 9.4 数据流

普通聊天：

1. 用户在 App 输入消息。
2. App 从本地读取会话上下文、Provider 配置和模型参数。
3. App 直接请求用户配置的模型 Provider。
4. App 流式展示回复。
5. App 将消息和结果写入本地数据库。

搜索新闻：

1. 用户选择新闻搜索入口，或模型请求调用搜索工具。
2. App 展示联网搜索确认。
3. App 调用工具网关的搜索接口。
4. 工具网关返回结构化搜索结果。
5. App 将搜索结果作为工具结果交给模型整理。
6. App 展示回答和来源引用。

代码验证：

1. 用户选择代码验证入口，或模型请求调用代码工具。
2. App 展示代码、语言、风险提示和确认按钮。
3. App 调用工具网关的代码执行接口。
4. 工具网关在沙箱中执行并返回 stdout、stderr、退出状态、执行时长。
5. App 将执行结果写入对话并展示。

### 9.5 工具网关接口要求

MVP 至少需要以下接口：

- `GET /health`：健康检查。
- `GET /v1/tools/manifest`：返回可用工具、权限级别、参数结构。
- `POST /v1/search`：执行网页或新闻搜索。
- `POST /v1/sandbox/run`：执行短代码。

接口要求：

- 所有接口必须有请求超时。
- 所有接口必须返回结构化错误。
- 高风险接口必须支持请求 ID，便于排查。
- 默认不记录完整用户输入。
- 日志必须脱敏。
- 搜索与代码执行结果要带时间戳。

## 12. 验收标准

### 12.1 App 验收

- 能添加一个 OpenAI-compatible Provider 并成功完成文本对话。
- 聊天回复支持流式展示和停止生成。
- 消息失败后能重试。
- Markdown、代码块、表格、图片消息能正常显示。
- 能生成一张图片并保存历史。
- 关闭 App 后重新打开，历史记录和配置仍存在。
- 清空数据后，本地聊天记录、Prompt、Provider 配置被删除。
- API Key 不出现在普通日志中。

### 12.2 工具网关验收

- 未配置工具网关时，基础聊天仍可正常使用。
- 配置工具网关后，App 能获取工具清单。
- 能搜索一条新闻，并在回答中显示来源链接。
- 能执行一段短 Python 或 JavaScript 代码，并展示 stdout、stderr、退出状态。
- 代码执行超时时，App 能展示结构化错误。
- 搜索失败时，模型不会编造搜索结果。

### 12.3 性能验收

- 冷启动进入主界面小于 1.5 秒。
- 打开会话列表无明显白屏。
- 长回复流式展示时输入区仍可操作。
- 取消生成后网络请求能停止。
- 图片历史列表不因加载原图卡顿。

## 13. 风险与对策

- 代码执行风险：必须通过工具网关沙箱执行，App 不直接执行用户代码。
- 搜索幻觉风险：搜索结果必须结构化返回，并展示来源链接和时间。
- OpenAI-compatible 差异风险：Provider 层做能力声明、连通性测试和兼容降级。
- 原生渲染复杂风险：MVP 先保证 Markdown、代码块、表格、LaTeX，Mermaid 可先降级为静态预览。
- 图片体积风险：使用缩略图缓存、原图按需加载、支持清理历史。
- 工具网关复杂化风险：网关只处理高风险工具，不介入基础聊天主路径。
