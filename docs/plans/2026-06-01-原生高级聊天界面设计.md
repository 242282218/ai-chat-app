# 原生高级聊天界面设计方案

> 日期：2026-06-01  
> 范围：Android App 的 Home 与 Chat 核心体验  
> 设计方向：Native Quiet Chat  
> 目标：把当前偏“功能工作台”的界面，收敛为轻量、高级、安卓原生的 AI 会话应用。

## 1. 结论

本次改造采用方案 B：Home + Chat 一起改成完整高级版。

当前 App 的能力已经足够多：多 Provider、Prompt、图片输入、图片生成、Tools、Gateway、导入导出、隐私设置、长上下文压缩、临时会话和敏感会话。问题不在能力少，而是首屏和聊天页同时暴露了过多能力，让用户感觉“应用很大”“像控制台”“不够高级”。

新的设计方向是 **Native Quiet Chat**：

- Home 是“会话中心”，不是功能入口集合。
- Chat 是“沉浸对话画布”，不是设置面板集合。
- Provider、Prompt、Tools、参数、危险操作全部进入渐进层级。
- 用 Android 原生 Material 3 承接复杂能力：FAB、ModalBottomSheet、TopAppBar、SearchBar、LazyColumn、语义色和系统字体。
- 高级感来自信息克制、留白、层级、语义色、触感反馈和状态清晰，而不是渐变、玻璃拟态、重阴影或装饰图形。

一句话定义：

```text
默认只看见会话、消息和输入；需要时再展开能力。
```

## 2. 调研摘要

### 2.1 参考项目

| 项目 | 观察 | 对本项目的启发 |
|---|---|---|
| RikkaHub | Android AI chat client，强调 Material You、多 Provider、多模态、MCP、Markdown、消息分支。 | 原生 Android AI 客户端不应照搬 Web 控制台；多能力可以存在，但默认界面要像移动应用。 |
| Conduit | 原生 iOS/Android Open WebUI 客户端，强调 secure storage、无第三方分析、WebSocket streaming、移动端体验。 | 移动端高级感来自“像原生 App”，不是把 Web 管理台搬到手机。 |

### 2.2 关键结论

同类优秀项目的共同点不是“页面花”，而是：

1. **聊天是中心对象**：模型、工具、知识库、图片都围绕当前聊天展开。
2. **配置不抢首屏**：Provider、参数和危险动作不常驻展示。
3. **移动端要少层级但强主路径**：用户打开 App 后只能有一个最明显的下一步。
4. **本地优先要可感知但不喧宾夺主**：隐私、安全、BYOK 信息应在设置和状态里表达，不需要占据主画布。
5. **高级感靠克制**：少色彩、少卡片、少说明文字、少按钮，同时保留足够的触达路径。

## 3. 当前问题

### 3.1 Home 过像“功能面板”

当前 Home 包含：

- 顶部 `AI Chat Workbench`
- 任务输入 Hero
- Quick Actions 网格
- 最近对话
- 搜索对话面板
- System Status
- 管理入口列表

这会让用户第一眼看到很多“能力”，但不知道最重要的动作是什么。对聊天 App 来说，Home 的核心应该是：

```text
继续一个会话
或创建一个会话
```

其他动作都是次级动作。

### 3.2 Chat 默认负担过重

当前 Chat 已经把会话、Provider、Prompt、参数、Tools、危险操作收进了控制区，但主界面仍有一个较重的 `ConversationContextBar`，并且输入栏包含状态行、说明文字、多个按钮，视觉上仍偏“工作台”。

Chat 的默认状态应该只回答三个问题：

```text
我在哪个会话？
现在有没有生成？
我在哪里输入？
```

### 3.3 视觉语言偏“面板化”

当前大量使用 `WorkbenchPanel`、边框、StatusPill、IconTile。它们适合管理页，但用于 Home 和 Chat 会让画面变重，形成“所有信息都很重要”的错觉。

新的 Home / Chat 应减少面板感：

- Home 列表项不使用卡片。
- Chat 消息不全都装进厚重容器。
- 状态 pill 只保留必要状态，不作为装饰。
- 主 CTA 只保留一个。

## 4. 设计原则

### 4.1 会话优先

Home 首屏只服务会话：

- 看最近会话。
- 搜索会话和消息。
- 创建新会话。
- 进入设置。

图片生成、Prompt、Tools 和数据管理不再作为首页平铺入口，而是进入创建 Sheet 或设置页。

### 4.2 默认轻，展开强

默认界面要轻：

- 少按钮。
- 少说明。
- 少边框。
- 少状态标签。

展开层要强：

- Bottom Sheet 内容要完整。
- 低频功能路径要明确。
- 危险操作要有确认。
- Provider 缺失要有恢复动作。

### 4.3 原生优先

坚持 Android 原生感：

- 使用 Material 3 组件，不做 Web 风格顶栏。
- FAB 只承载当前页面最主要动作。
- Bottom Sheet 用于创建、控制、会话管理。
- 搜索用顶部 SearchBar 或搜索模式，而不是常驻搜索卡片。
- 使用系统字体和 Material typography，不引入复杂字体。
- 点击使用 ripple；长按、复制、重试等操作使用熟悉的移动端模式。

### 4.4 高级感来自秩序

高级感的可执行标准：

- 每个屏幕只有一个视觉锚点。
- 主色面积控制在 5%-10%。
- 大面积使用温暖中性色。
- 列表靠排版和留白分隔，不靠重卡片。
- 阴影只用于浮层、FAB、底部输入容器。
- 文案短，不解释显而易见的功能。

### 4.5 功能不删，只降噪

这次不是砍功能。功能层级调整如下：

| 层级 | 内容 | 展示方式 |
|---|---|---|
| L1 常驻 | 最近会话、当前聊天、输入、发送、停止 | Home / Chat 主界面 |
| L2 一步展开 | 新建普通会话、临时会话、图片生成、搜索 | FAB Sheet / Search 模式 |
| L3 控制层 | Provider、模型、参数、Prompt、Tools、会话列表 | Chat More Sheet |
| L4 管理层 | Provider 编辑、Prompt 管理、Gateway、备份、清空数据 | Settings / 独立管理页 |
| L5 高风险 | 删除、归档、清空上下文、导入覆盖、工具执行确认 | Dialog + 明确影响说明 |

## 5. 信息架构

### 5.1 新结构

```text
Home 会话中心
├─ 顶部动作：搜索 / 设置
├─ 标题：会话
├─ 状态提示：仅在 Provider 缺失或异常时出现
├─ 会话列表：最近对话
├─ 搜索模式：本地消息搜索结果
└─ 创建 FAB
   └─ 创建 Sheet
      ├─ 新建会话
      ├─ 临时会话
      ├─ 图片生成
      └─ 从 Prompt 开始

Chat 沉浸对话
├─ Top Bar：返回 / 会话标题 / 更多
├─ Subline：Provider + Model + 临时/敏感/生成状态
├─ Message Canvas：消息、图片、工具结果、压缩摘要
├─ Pending Tool Confirmation：仅在需要确认时出现
├─ Error Banner：仅在错误时出现
└─ Composer：图片、输入、发送/停止
   └─ More Sheet
      ├─ 会话切换与标题编辑
      ├─ Provider / Model
      ├─ 参数
      ├─ Prompt
      ├─ Tools
      └─ 危险操作
```

### 5.2 页面关系

```text
Home
├─ 点击会话 -> Chat(conversationId)
├─ 点击创建会话 -> Chat(new)
├─ 点击临时会话 -> Chat(new, temporary = true)
├─ 点击图片生成 -> Images
├─ 点击设置 -> Settings Hub
└─ 搜索结果点击 -> Chat(conversationId)

Chat
├─ 返回 -> Home
├─ 更多 -> Control Sheet
├─ 配置 Provider -> Providers
├─ Prompt 管理 -> Prompts
├─ Tools 管理 -> Tools
└─ 数据设置 -> Settings
```

## 6. Home 详细设计

### 6.1 默认布局

参考用户提供截图，Home 使用轻量布局：

```text
[status bar]

[search icon]                              [settings icon]

会话

[conversation row]
[conversation row]
[conversation row]
...

                         [+  创建会话]
```

实现建议：

- 使用 `Scaffold`。
- 不使用传统标题型 `TopAppBar`，改为自定义顶部动作行，保留状态栏下方留白。
- 内容使用 `LazyColumn`。
- 右下角使用 `ExtendedFloatingActionButton`。
- 列表底部 padding 必须大于 FAB 高度，避免遮挡最后一项。

### 6.2 顶部动作区

结构：

- 左侧：搜索图标按钮。
- 右侧：设置图标按钮。
- 两者都为 48dp 点击热区。
- 图标视觉大小 24dp。

交互：

- 点击搜索：进入搜索模式。
- 点击设置：打开设置入口。若当前没有 Settings Hub，先进入现有 Data Settings 或展示管理 Sheet。

设计要求：

- 顶部不写 App 名。
- 不显示多余状态 pill。
- 搜索和设置不使用文字按钮。

### 6.3 标题

标题：

```text
会话
```

样式：

- `headlineLarge` 或接近 34sp 的 Material typography。
- FontWeight.Normal 或 Medium，避免过粗。
- 颜色使用 `onBackground`。
- 顶部动作区与标题之间保留 64dp 左右节奏，形成参考图的高级留白。

### 6.4 会话列表项

单条结构：

```text
[message icon]  标题
                使用 rchat
```

字段映射：

- 标题：`Conversation.title`。
- 副信息优先级：
  1. `使用 <defaultModel>`
  2. `临时会话`
  3. `敏感会话`
  4. `最近更新`

若能从当前 Provider 推导 Provider 名，副信息可以扩展为：

```text
使用 <Provider> / <Model>
```

视觉：

- 行高建议 72dp-84dp。
- 左 icon 为线性消息图标，不放在色块里。
- 不使用 Surface 卡片。
- 不画完整边框。
- 可使用极淡分隔线或完全依赖间距。
- 标题单行省略。
- 副信息单行省略，颜色为 `onSurfaceVariant`。

点击：

- 点击整行进入对应 Chat。
- 行点击使用 ripple。
- 不在行内放更多按钮，避免视觉杂乱。

### 6.5 空状态

当没有会话：

```text
还没有会话
创建一个会话，开始保存你的 AI 工作流。
```

动作：

- 主动作仍然是右下角 FAB。
- 空状态内部可以有一个轻量 TextButton：`创建会话`。

禁止：

- 不使用大插画。
- 不使用大卡片。
- 不写长说明。

### 6.6 Provider 缺失状态

当没有 enabled Provider 时，Home 顶部标题下方出现一个轻量提示行：

```text
需要配置 Provider 才能发送消息
[配置]
```

设计：

- 使用浅 warning container 或 surface 低强调样式。
- 不占据大面积。
- 点击配置进入 Provider 页面。

目的：

- 告诉用户为什么创建后可能不能发。
- 不把 Provider 管理变成首页主内容。

### 6.7 搜索模式

点击搜索图标后进入搜索模式：

```text
[back icon] [搜索消息                  ]

搜索结果
[result row]
[result row]
```

状态：

- 输入为空：显示 `输入关键词搜索本地消息`。
- 有结果：显示消息匹配片段。
- 无结果：显示 `没有找到相关消息`。

搜索结果项：

```text
[message icon]  会话标题
                ...匹配片段...
```

交互：

- 返回图标退出搜索模式，保留原 Home。
- 点击结果进入 Chat。
- 搜索 query 更新沿用当前 `HomeViewModel.updateSearchQuery`。

### 6.8 创建会话 FAB

FAB 是 Home 唯一强 CTA。

默认：

```text
+ 创建会话
```

行为：

- 如果只有“新建会话”一个动作，点击直接进入 Chat。
- 本项目有临时会话、图片生成、Prompt 等相关创建动作，因此点击打开创建 Sheet 更合适。

创建 Sheet 内容控制在 3-5 项：

| 项 | 说明 | 目标 |
|---|---|---|
| 新建会话 | 普通持久会话 | Chat(new) |
| 临时会话 | 退出后清理 | Chat(new, temporary) |
| 图片生成 | 进入图片创作 | Images |
| 从 Prompt 开始 | 选择 Prompt 后进入 Chat | Prompt selector 或 Prompts |

Material 指南强调 FAB 应代表屏幕主动作，且一个屏幕只应有一个 FAB。这里主动作是“创建”，Sheet 内选项都属于创建路径，符合该原则。

## 7. Chat 详细设计

### 7.1 默认布局

```text
[back]  会话标题                         [more]
        Provider / Model · 状态

[message canvas]

[tool confirmation if needed]
[error banner if needed]

[composer]
```

主变化：

- 移除主界面的重型 `ConversationContextBar` 卡片。
- TopBar 直接承载会话标题和状态副标题。
- 消息区增加纵向空间。
- 输入栏变轻，减少解释性文字。

### 7.2 Top Bar

左侧：

- 返回按钮。

中间：

- 第一行：会话标题。
- 第二行：Provider / Model / 状态。

右侧：

- 更多按钮。

副标题示例：

```text
rchat / gpt-4.1
rchat / gpt-4.1 · 生成中
临时会话 · rchat / gpt-4.1
需要 Provider
```

规则：

- 状态只保留最关键一个：生成中、临时、敏感、需要 Provider。
- 不显示消息数量，除非进入控制 Sheet。
- 副标题单行省略。

### 7.3 Message Canvas

目标：

- 消息内容成为页面主角。
- 减少管理面板感。
- 保留复制、编辑、重试、折叠工具结果等能力。

消息样式：

| 角色 | 布局 | 背景 | 宽度 |
|---|---|---|---|
| User | 右对齐 | `primaryContainer` 或薄荷浅色 | 最大 86%-88% |
| Assistant | 左对齐 | 透明或 `surface` 极弱层 | 最大 96%-100% |
| Tool | 左对齐，可折叠 | `secondaryContainer` 弱色 | 最大 96% |
| System / Compressed | 居中或左侧说明块 | `surfaceContainer` | 最大 96% |

消息头：

- 默认不显示大 pill。
- User 显示“你”可省略。
- Assistant 显示模型名可选，建议只在第一条或长按详情中展示。
- Failed / Cancelled / Streaming 必须可见。

消息操作：

- 常用：复制、重试、编辑。
- 默认可在消息底部轻量显示，或点击消息后展开。
- Tool 消息默认折叠，避免占据阅读空间。

### 7.4 空对话

如果 Provider 已配置：

```text
开始新的会话
输入问题、粘贴材料，或添加图片。
```

如果 Provider 未配置：

```text
还不能发送消息
先配置 Provider，请求会从本机发送到你的 endpoint。
[配置 Provider]
```

视觉：

- 中部轻量文字。
- 不使用重卡片。
- 不显示多个状态 pill。

### 7.5 生成状态

生成中不再用多个 pill 堆叠，而使用两个位置表达：

1. TopBar 副标题显示 `生成中`。
2. Composer 发送按钮变为停止按钮。

可选增强：

- Assistant 正在 streaming 的消息尾部显示轻量进度点。
- 不使用全屏 loading。
- 不阻塞用户滚动和复制旧消息。

### 7.6 错误状态

错误使用轻量 banner：

```text
生成失败：<简短原因>
[重试] [编辑输入]
```

规则：

- 错误不应只显示红字。
- 必须给恢复路径。
- 不使用 Dialog，除非是高风险确认或权限问题。

### 7.7 Tool 调用确认

Tool 确认是高风险路径，保留明确面板，但要更原生：

```text
允许工具调用？
<tool display name>
权限：只读 / 网络 / 执行代码 / 高风险
[拒绝] [允许]
```

视觉：

- 放在输入栏上方。
- 使用 `surface`，轻边框。
- 高风险使用 error 或 warning。

交互：

- 确认后面板消失。
- 拒绝后消息流继续记录结果。
- Tool 参数默认折叠，可点击展开。

### 7.8 Composer

目标：

- 像移动聊天 App。
- 保持 AI 能力。
- 少解释。

结构：

```text
[image/add] [text field              ] [send/stop]
```

细节：

- 外层可以是底部浮起的 Surface。
- 圆角 16dp 或 20dp，但不要过度胶囊化。
- TextField 不显示长 label，使用 placeholder：`输入消息`。
- 图片按钮为 IconButton，不用 OutlinedButton。
- 发送按钮为 FilledIconButton 或小 Button。
- 生成时发送按钮变 Stop。
- 编辑消息时在输入栏上方显示一条轻量状态：`正在编辑消息` + `取消`。
- Provider 缺失时输入仍可编辑，但发送按钮 disabled，并提供 `配置 Provider` 入口。

图片草稿：

- 在输入框上方以 64dp thumbnail 横向显示。
- 删除按钮覆盖在缩略图右上角。
- 不要让图片草稿撑高整个输入区过多。

### 7.9 Control Sheet

更多按钮打开 Chat Control Sheet。Sheet 是复杂能力的承载层。

分组顺序：

```text
当前会话
├─ 标题编辑
├─ 会话切换
└─ 新建 / 临时

模型
├─ Provider
├─ Model
└─ 配置 Provider

输入增强
├─ Prompt
└─ Tools

参数
├─ Temperature
├─ Top P
├─ Max Tokens
└─ 保存偏好

危险操作
├─ 清空上下文
├─ 归档对话
└─ 删除对话
```

Sheet 设计：

- 每组用标题 + 内容，不全用 `WorkbenchPanel`。
- 重要操作用 Filled / Tonal Button。
- 危险操作统一放底部，使用 error 色和确认 Dialog。
- 会话切换可以用 LazyRow chip 或轻量列表。
- Provider 缺失时，模型组第一屏显示配置引导。

## 8. 视觉系统

- Chat 默认只展示对话和输入，不展示配置面板。

- 主色面积不超过 10%。

## 13. 风险与取舍

### 13.1 功能可见性下降

风险：

- Provider、Prompt、Tools 不再在首页平铺，用户可能第一眼不知道有这些能力。

缓解：

- 创建 Sheet 提供关键入口。
- Chat More Sheet 分组清晰。
- Settings 入口保留。
- 空状态和 Provider 缺失状态提供恢复路径。

### 13.2 Home 不再直接输入任务

风险：

- 旧 Home 的 task composer 可以直接带草稿进入 Chat，新 Home 会少一个快捷输入。

取舍：

- 移动聊天 App 更常见路径是先进入会话再输入。
- 可以在创建 Sheet 中保留“从输入开始”的轻入口，但不建议首期加复杂输入框。

### 13.3 Chat Sheet 内容仍可能很重

风险：

- 把复杂能力都放进 Sheet，Sheet 可能变成新控制台。

缓解：

- Sheet 分组。
- 默认折叠高级参数。
- 危险操作放底部。
- 避免每组都套卡片。

### 13.4 主题色主观差异

风险：

- 用户可能更喜欢当前陶土色或参考图薄荷色。

推荐：

- 采用灰绿/薄荷作为主方向。
- 保持低饱和，避免“可爱化”。
- 后续可以增加动态色开关，但本次不扩大范围。

## 14. 非目标

本次不做：

- 新增复杂 Settings Hub 的完整信息架构。
- 新增桌面/平板双栏布局。
- 新增完整设计系统文档站。
- 新增动画系统。
- 新增消息分支、RAG、MCP 能力。
- 重写 Provider 或 Gateway 业务逻辑。
- 为单次 UI 改造引入新 UI 框架。

## 15. 推荐实现策略

推荐按“先主路径，后复杂层”的顺序实现：

1. 改主题色。
2. 重构 Home 为会话列表。
3. 加 Home 搜索模式。
4. 加 Home 创建 Sheet。
5. 改 Chat TopBar。
6. 降噪 Chat MessageList 和 Empty state。
7. 改 Composer。
8. 重排 Chat Control Sheet。
9. 跑测试和 lint。

每一步都保持可运行，避免一次性大改导致难以定位问题。

## 16. 最终效果描述

完成后，App 的第一感受应从：

```text
这是一个功能很多的 AI 工具工作台。
```

变成：

```text
这是一个安静、可靠、原生的 AI 会话应用。
```

用户打开 App 看到的是会话，而不是功能清单；进入 Chat 看到的是消息和输入，而不是配置集合。复杂能力仍然完整存在，但被放到更符合移动端心智的位置。
