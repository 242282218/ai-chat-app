# 移动端 Codex 工作台重构蓝图

日期：2026-06-04  
目标执行者：Codex  
范围：Android App 为主，Gateway 作为可选增强，不作为第一路径依赖。

## 1. 目标

把当前原生 Android AI 聊天应用重构为 **移动端 Codex 工作台**：用户在手机上通过对话发起任务，模型能选择工具、请求授权、执行本地或联网能力，并把结果回写到聊天流。最终体验不是“更好看的聊天 App”，而是“能聊天、能查新闻、能生成图片、能测试 API、能读文件、能执行受限 JS、能辅助写代码”的轻量原生移动工作台。

第一阶段必须同时推进体验和能力：

- 美学与交互达到成熟移动 App 水准。
- 工具调用能形成闭环，而不是只有静态工具列表。
- 图片生成可从聊天直接触发，也可在图片工作室细调。
- 模型设置按能力分组：对话模型、图片模型、工具模型、代码模型。
- 尽量 App 本地完成；Gateway 只作为高级沙箱、重型搜索或远端执行兜底。

## 2. 已确认产品决策

- 路线选择：方案 C，移动 Agent 工作台。
- 导航结构：底部 4 Tab，`对话 / 工具 / 图片 / 设置`。
- 工具交互：对话内工具卡 + 工具中心管理。
- 图片交互：聊天直接生成 + 图片工具卡展示 + 图片页做高级参数和历史。
- 执行位置：尽量 App 本地完成，不依赖 Gateway。
- 本地代码执行：第一阶段支持受限 JavaScript，不支持任意系统命令。
- 视觉方向：以 LobeChat / Open WebUI 的工具与模型管理感为主，吸收 RikkaHub / GPT Mobile 的原生 Android 轻量移动交互。
- Provider 设置：Provider + 模型能力分组，不只做简单双模型。

## 3. 当前代码基础

当前项目已经具备以下基础，应复用而不是推倒重写：

- Android：Kotlin、Jetpack Compose、Material 3、Room、Koin、OkHttp、kotlinx.serialization。
- Provider：OpenAI、OpenAI-compatible、NewApi、Sub2Api、Custom、OpenRouter、Ollama 注册在 `ProviderRegistry`。
- 对话：`ChatViewModel`、`GenerationController`、`ToolExecutor` 已能接入工具调用。
- 图片：`OpenAiImageGenerationProvider` 已调用 OpenAI-compatible `/images/generations`，并支持 URL 下载为 base64。
- 工具结果：`ToolInvocationRepository`、`ToolResult`、`ToolStatus` 已可保存运行记录。
- 导航：当前已有 `Conversations / ImageGen / ToolsHub / SettingsHub` 四个底部 Tab 雏形。
- 本地工具：`BuiltInToolRegistry` 当前只有 `time` 和 `image_generation`，需要扩展。
- 远端工具：`web_search` 和 `code_sandbox` 当前依赖 Gateway，后续改为本地优先、Gateway 可选。

敏感信息规则：

- 不把 API Key 写入源码、文档、测试 fixture 或提交记录。
- 用户提供的测试 key 只允许通过本机安全输入、Android Keystore、GitHub Secrets 或 `.env` 占位读取。
- 文档和代码只能写占位符，例如 `NEWAPI_API_KEY`、`NEWAPI_IMAGE_KEY`。

## 5. 信息架构

主导航固定 4 个同级区域：

1. `对话`
   - 主入口。
   - 普通聊天、工具调用、搜索新闻、图片生成、文件读取、本地 JS 执行、代码生成都从这里发起。
   - 工具结果以内联卡片形式回到聊天流。

2. `工具`
   - 工具中心，不是执行主入口。
   - 管理工具开关、权限策略、运行历史、失败日志、调试入口。
   - 支持重跑工具、复制参数、查看原始响应。

3. `图片`
   - 图片工作室。
   - 管理图片模型、尺寸、质量、数量、历史、重新生成、API 测试。
   - 聊天触发图片生成时复用同一图片能力。

4. `设置`
   - Provider、API Key、模型能力分组、Prompt 预设、数据备份、安全隐私、主题。
   - 不把高级配置塞到聊天页。

主任务流：

```text
用户输入任务
→ 模型判断是否需要工具
→ App 展示工具计划卡
→ 用户允许 / 拒绝 / 修改参数
→ 本地工具或 Provider API 执行
→ 工具结果卡回写聊天流
→ 模型基于结果继续总结、写代码或给下一步建议
```

## 6. 视觉与交互原则

核心气质：移动端工具工作台、清晰、可信、低装饰、高可控。

必须做到：

- 使用 Android 原生支持组件：Jetpack Compose、Material 3、Navigation Compose、Android 文件选择器、Room、Keystore、OkHttp。
- 禁止用 WebView 承载核心 UI。
- 禁止为视觉效果引入重型跨平台 UI 框架。
- 首屏必须展示真实可操作内容：对话输入、最近任务、工具状态，而不是品牌宣传。
- 点击目标不小于 44dp；危险操作必须确认或可撤销。
- 键盘弹出时输入框、发送、附件、工具按钮仍可访问。
- 工具状态覆盖 `queued / needs_approval / running / streaming / completed / failed / denied / canceled`。
- 错误状态必须给恢复路径：重试、修改参数、打开设置、复制日志。

色彩建议：

- 亮色：白底或暖白工作台，内容优先。
- 暗色：LobeChat/Open WebUI 的工具感 + Linear Dark 克制层级。
- Accent 只用于主操作、活动工具、选中模型和关键状态，不大面积铺满。
- 状态色必须配文字和图标，不能只靠颜色。

布局建议：

- 对话页：顶部轻标题 + 模型胶囊 + 聊天流 + 底部输入栏。
- 工具卡：轻边框、紧凑标题、状态标签、参数摘要、展开详情。
- 工具中心：列表优先，少用大卡片；每行展示工具名、权限、开关、最近状态。
- 设置页：分组列表，不做复杂仪表盘。

## 7. 工具体系

### 7.1 工具分层

低风险工具，默认可直接运行：

- `time`：本机时间。
- `text_transform`：本地文本清洗、JSON 格式化、正则预览、大小写转换。
- `code_diff_preview`：展示代码 diff，不写文件。

中风险工具，首次确认，可按会话记住：

- `web_search_local`：App 端联网搜索或新闻检索。
- `image_generation`：调用图片 Provider。
- `provider_connection_test`：测试 Provider、对话模型、图片模型。

高风险工具，每次必须明确授权：

- `file_read`：读取用户通过系统文件选择器授权的文件。
- `local_js`：执行受限 JavaScript。
- `image_upload_to_model`：把本地图片发送给模型。

第一阶段禁止实现：

- 任意 shell 命令。
- 后台自动执行工具。
- 绕过 Android 文件选择器读取任意路径。
- 无提示上传文件或图片。
- 本地 Python/Node/Go 完整运行时。

### 7.2 对话内工具卡

新增统一组件：

- `ToolPlanCard`：展示模型计划调用的工具、参数摘要、风险级别。
- `ToolApprovalSheet`：高风险工具的确认面板，可修改参数或拒绝。
- `ToolRunningCard`：运行中状态，显示耗时、停止按钮、简短日志。
- `ToolResultCard`：成功结果，可展开、复制、引用、让模型继续处理。
- `ToolErrorCard`：失败结果，显示错误、恢复动作和日志复制。

消息流分发规则：

- 文本消息：`MessageBubble`。
- 图片结果：`ImageResultCard`，同时作为工具结果展示。
- 工具计划：`ToolPlanCard`。
- 工具结果：`ToolResultCard` / `ToolErrorCard`。
- 代码产物：`CodeBlockCard`，支持复制、分享、生成 diff。

### 7.3 工具中心

`ToolsHubScreen` 重构为三段：

- `工具`：启用状态、权限级别、最近运行。
- `历史`：按会话、工具、状态筛选运行记录。
- `调试`：查看 schema、构造测试参数、重跑最近一次。

工具详情页字段：

- 显示名、描述、输入 schema、输出 schema。
- 风险级别和权限策略。
- 是否联网、是否读取文件、是否发送 Provider。
- 最近 10 次运行记录。

## 8. 本地 JavaScript 执行

第一阶段使用受限 JavaScript 作为本地代码执行能力。

优先技术路线：

- 使用 AndroidX JavascriptEngine 的 `JavaScriptSandbox` / `JavaScriptIsolate`。
- 执行前调用支持性检查；不支持时禁用工具并展示原因。
- 依赖版本由 Codex 执行时按 `gradle/libs.versions.toml` 查询最新可用稳定/可接受版本，不硬编码过时版本。
- 官方参考：https://developer.android.com/jetpack/androidx/releases/javascriptengine

安全边界：

- 不提供 `fetch`、文件系统、系统命令、Android Context。
- 输入通过 JSON 字符串显式传入。
- 默认无网络。
- 限制执行时间，超时标记 `timed_out`。
- 限制输出长度，超长标记 `truncated`。
- 支持取消执行。
- 结果以 JSON 输出回写工具结果。

建议 API：

```kotlin
interface LocalScriptRunner {
    suspend fun run(request: LocalScriptRunRequest): LocalScriptRunResult
}

data class LocalScriptRunRequest(
    val language: ScriptLanguage,
    val code: String,
    val inputJson: String?,
    val timeoutMillis: Long,
    val outputLimitBytes: Int,
)
```

第一阶段只允许：

- `ScriptLanguage.JavaScript`
- JSON 处理
- 正则测试
- 算法片段验证
- 文本转换

不承诺：

- 运行 npm 包。
- 读写项目文件。
- 执行 Android 自动化。
- 替代桌面 Codex 沙箱。

## 9. 搜索与新闻

第一阶段搜索优先 App 本地 HTTP 实现，Gateway 可选：

- 新增 `LocalSearchClient`，使用 OkHttp 调用用户配置的搜索 Provider。
- 支持 Tavily、Brave、Exa、Perplexity-like OpenAI-compatible 搜索代理中的至少一种，具体按用户可配置 API Key 决定。
- 没有搜索 Provider 时，工具卡提示去设置页配置。
- 搜索结果必须包含标题、摘要、URL、来源、时间。
- 聊天总结必须保留引用入口，不把搜索结果吞成无来源结论。

如果没有可用搜索 API，不要硬编码第三方免费接口。保留 Gateway 搜索作为兼容路径。

## 10. 图片生成

图片生成必须同时支持两条入口：

1. 对话内直接触发：
   - 用户说“生成一张……”或模型选择 `image_generation` 工具。
   - 工具卡展示 prompt、模型、尺寸、数量、状态。
   - 生成结果以内联图片卡展示，支持保存、分享、重新生成、复制 prompt。

2. 图片工作室：
   - 支持 Provider、模型、尺寸、质量、数量。
   - 支持历史、失败重试、重新生成、引用到聊天。
   - 支持 API 测试。

newapi 测试配置：

- Base URL：`https://zzshu.cc`
- 对话接口：OpenAI-compatible chat/completions 或 responses，按 Provider 当前实现选择。
- 图片接口：`/v1/images/generations`
- API Key：只能从安全存储或测试环境变量读取，不写入文档和源码。
- 建议占位名：`NEWAPI_API_KEY`、`NEWAPI_IMAGE_KEY`。

验收：

- 设置对话模型后能发送普通消息。
- 设置图片模型后能从图片页生成。
- 聊天里触发图片工具后能生成图片并回到聊天流。
- 401/429/5xx 有清晰错误文案和重试路径。

## 11. 模型与 Provider

Provider 设置页重构为两层：

1. Provider 列表
   - 名称、类型、Base URL、启用状态、测试状态。
   - 支持新增、编辑、删除、启用、禁用。
   - API Key 存 Keystore，不显示明文。

2. 模型能力分组
   - 对话模型：默认聊天。
   - 图片模型：`/v1/images/generations`。
   - 工具模型：更适合 tool calling 的模型。
   - 代码模型：更适合代码生成、解释、diff。

数据层建议：

- 复用已有 `ModelConfig` 和 `ModelCapability`。
- 若现有 model preference 只够单默认模型，新增能力偏好表或扩展现有 DAO。
- Room schema 变更必须升级 version、增加 migration、更新 schema JSON 和迁移测试。

模型选择规则：

- 当前会话可临时覆盖默认对话模型。
- 图片工具优先使用图片模型。
- 代码任务优先使用代码模型，没有则回退对话模型。
- 工具规划优先使用工具模型，没有则回退对话模型。
- 模型不支持工具调用时，App 不传本地 function tools，只执行普通聊天。

## 12. 文件读取

第一阶段只做用户显式选择的文件：

- 使用 Android `ActivityResultContracts.OpenDocument`。
- 支持文本、Markdown、JSON、常见代码文件。
- 图片只读取元信息或作为多模态输入，上传前必须确认。
- PDF/DOCX 可先提示“不支持解析”，不引入重型解析库；后续再评估。

文件结果卡展示：

- 文件名、类型、大小、读取状态。
- 文本预览前 N 行。
- 是否已发送给模型。
- 可移除、重新选择。

不做：

- 扫描文件夹。
- 自动上传全部附件。
- 后台读取外部存储。

## 13. 代码辅助能力

第一阶段目标：

- 生成代码。
- 解释代码。
- 给出 patch/diff。
- 本地 JS 片段验证。
- 复制、分享、保存到聊天产物。

不做：

- 改写本机任意项目文件。
- 手机本地运行 Python/Go/Rust/Gradle。
- Git 操作。
- 长时间后台构建。

高级能力预留：

- Gateway `code_sandbox`：运行 Python 或其他语言。
- 远端任务执行：未来可接入自有沙箱。
- 项目文件编辑：必须另行设计权限、文件树、diff 审批和恢复。

## 14. 数据与状态

新增或调整的数据对象：

- `ToolDescriptor`：补充 `riskLevel`、`requiresNetwork`、`requiresFileAccess`、`defaultPermissionPolicy`。
- `ToolInvocation`：补充 `conversationId`、`inputPreview`、`rawInputJson`、`rawOutputJson`、`durationMs`、`canceledAt`。
- `ModelRolePreference`：Provider + capability role + model。
- `ToolPermissionPolicy`：tool name + scope + policy。
- `Artifact`：图片、代码、搜索结果、文件摘要等可复用产物，第一阶段可先不建独立表，先用消息和工具结果承载。

Room 规则：

- 改 entity/DAO/Database 必须升级 schema version。
- 同步 migration。
- 更新 schema JSON。
- 补迁移测试。
- 不破坏旧聊天、图片历史、Provider 配置和 API Key。

### Phase 10：总体验验收

必须完成的端到端场景：

1. 配置 NewApi 对话 Provider，测试连接成功。
2. 配置图片模型，图片页生成成功。
3. 在聊天中输入“生成一张……”，工具卡出现，允许后生成图片。
4. 在聊天中要求“搜索今天某新闻并总结”，搜索卡出现，结果带来源。
5. 在聊天中要求“运行这段 JS 处理 JSON”，授权后返回执行结果。
6. 选择一个 Markdown 文件，要求模型总结，读取卡和总结都出现在聊天流。
7. 让模型写一段代码，代码卡可复制。
8. 断网、401、429、Provider 500 都有可恢复错误卡。

如果涉及 Gateway：

```powershell

go test ./...
```

## 16. Codex 执行守则

- 先读现有代码和 git diff，再改。
- 不回滚用户已有未提交改动。
- 小步提交式实现，但不要自动 commit，除非用户明确要求。
- 每个 Phase 都必须有可运行验证。
- UI 改动必须用 Compose 原生组件。
- 不引入 WebView 核心 UI、不引入 Flutter/React Native。
- 只在收益明确时添加依赖。
- Room 改动必须带 migration 和测试。
- API Key 永远不落仓库。
- 文档和新增 docs 文件名必须包含中文描述。

## 17. 完成标准

这个重构完成后，用户应能在手机上完成：

- 像聊天 App 一样自然对话。
- 像 Codex 一样把任务拆成工具调用。
- 搜新闻并保留来源。
- 生成图片并在聊天中看到结果。
- 设置对话模型和图片模型。
- 测试 Provider/API Key。
- 读取用户选择的文件。
- 运行受限 JS 完成轻量代码/数据任务。
- 查看每次工具调用的参数、权限、状态和结果。

达不到以上闭环时，不应发布正式 Release；只能作为内部测试构建。
