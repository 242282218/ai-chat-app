# 图片生成配置流重构设计

## 背景

当前 Android 客户端已经具备 Kotlin、Jetpack Compose、ViewModel、Room、DataStore、Retrofit 和 Coroutines 基础架构。图片生成通过可配置 Provider 调用 OpenAI-compatible `/v1/images/generations` 接口，API Key 存在本地安全存储中，不写入源码或文档。

第一阶段重构聚焦图片生成配置流，目标是让页面就绪状态、ViewModel 校验和实际网络请求保持一致。

## 方案

采用分阶段内聚重构，不重建 app 模块。保留现有 data/domain/provider 分层、Room schema、DataStore 偏好和发布流程，只收紧图片生成模块边界。

本阶段改动：

- 图片页 UI 就绪状态不再只依赖 `apiKeyRef`，而是基于 ViewModel 查询到的真实 API Key 可用性。
- ViewModel 在图片 Provider 列表变化后刷新密钥可用性，并把结果写入 `ImageGenerationUiState`。
- 保持 `API_BASE_URL`、`API_KEY`、`IMAGE_API_KEY` 为配置概念，不保存真实密钥到源码、文档或测试 fixture。
- 继续复用 Retrofit 图片 Provider，实际 endpoint 保持 `/v1/images/generations`。

## 数据流

```text
ProviderConfigRepository.observeProviders()
  -> ImageGenerationViewModel 过滤支持图片生成的 Provider
  -> 查询每个 Provider 的真实 API Key 是否可用
  -> ImageGenerationUiState.providerApiKeyAvailable
  -> ImageDrafts.imageGenerationReadiness()
  -> Compose 页面显示就绪、警告或错误状态
```

## 错误处理

- 没有支持图片生成的 Provider：提示先配置模型服务。
- Provider 需要 API Key 但密钥不可用：提示补全密钥。
- Prompt、Model、Count 无效：继续使用现有本地校验。
- Provider 运行时错误：继续通过 `providerFailureSummary` 输出可恢复诊断。
