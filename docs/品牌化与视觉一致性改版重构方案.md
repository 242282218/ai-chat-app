# 品牌化与视觉一致性改版重构方案

日期：2026-07-01

## 1. 结论先行

本次改版建议把 App 从泛化的“AI 聊天”升级为更明确的 **AI 工作台** 品牌系统：一个本地优先、可信、安静但有创作感的模型对话与图像生成工具。

推荐方向是 **静谧工作台 / Quiet Workbench**：

- 保留当前项目已经形成的 emerald 绿色识别，不大换血。
- 用中性浅灰/深灰做主画布，降低“全屏绿色”的单调感。
- 给图片生成引入更独立的 cyan / violet 辅助色，但只在创作状态、画布、作品库中使用。
- 给警告、模型连接、失败恢复继续使用 warm amber / red，保持语义稳定。
- 新增完整 App 图标、启动图、空状态插画、品牌图形母题和设计 token，避免只靠 Material Icons 拼界面。

这不是一次“换皮”。目标是建立可持续的视觉规则，让聊天、图片生成、模型连接、设置、错误恢复、空状态、截图和后续 Release 物料看起来来自同一个产品。

## 2. 项目现状依据

已检查当前项目文件、文档、截图和 UI 代码。当前基线如下：

- 项目定位：原生 Android AI 聊天应用，本地优先存储，聚焦聊天和图片生成。
- 技术栈：Kotlin、Jetpack Compose、Material 3、Room、Koin、OkHttp、kotlinx.serialization。
- 当前主题：`app/src/main/java/com/aichat/workbench/ui/theme/Theme.kt`
  - 主色是 Refined Emerald：`#0A8F5C` / dark `#34D399`
  - 浅色背景：`#F8FAFB`
  - 深色背景：`#09090B`
  - Typography 已按 Material roles 定义，字距为 0。
  - Shapes 偏大圆角：8 / 10 / 14 / 18 / 28dp。
- 当前间距：`WorkbenchSpacing` 已有 4dp baseline 和 8dp rhythm。
- 当前动效：`WorkbenchMotion` 使用 spring，已有 reduced motion 工具。
- 当前界面：
  - 聊天页已有顶栏、会话抽屉、搜索、输入区、消息操作。
  - 图片生成页已有表单、参数折叠、作品库、模型连接提示。
  - 设置页已形成“模型服务 / 图片生成 / 数据与隐私 / 外观 / 关于”的结构。
  - Provider 页已有健康状态、连接列表、底部编辑 sheet。
- 当前资源缺口：
  - `app/src/main/res` 下未看到 launcher icon / adaptive icon 资源。
  - `AndroidManifest.xml` 未显式声明 `android:icon` / `android:roundIcon`。
  - `strings.xml` 仍是 `AI 聊天`，品牌记忆点弱。
- 当前截图观感：
  - 优点：留白充足、中文直接、模型未配置状态清楚、绿色主色已有识别。
  - 问题：视觉母题弱，空状态和功能图标过于通用；图片生成与聊天页气质差异不足；底栏/大标题/圆角容易显得像“组件堆叠”而不是成熟品牌。

## 3. 设计目标

### 3.1 产品目标

- 用户一眼知道这是一个“本地优先的 AI 工作台”，不是普通聊天壳。
- 聊天、图片生成、模型连接三类核心能力彼此有区分，但共享一套品牌骨架。
- 降低首次配置模型的心理成本，让“没有模型服务”从错误变成明确的设置步骤。
- 保持移动端高效率：少装饰、少营销感、少无意义动画。
- 为后续设置外观、截图验收、Release 物料、应用商店图像打基础。

### 3.2 视觉目标

- **可信**：本地优先、密钥安全、模型连接透明。
- **安静**：界面留白足够，消息内容优先，不用强烈霓虹和复杂背景。
- **专业**：状态、错误、输入、模型参数都像工具，不像玩具。
- **有创作感**：图片生成区域有画布、图像、光标、生成轨迹等视觉语言。
- **一致**：颜色、圆角、图标、动效、空状态、文案都能复用。

### 3.3 非目标

- 不引入新的前端技术栈。
- 不把 App 改成 WebView 或网页风格落地。
- 不引入 Stream Chat SDK、shadcn/ui、Tailwind 等依赖到 Android App；它们只作为设计参考。
- 不做复杂吉祥物、3D mascot 或高成本插画系统。
- 不为了品牌化牺牲可读性、触控尺寸、动态字体和深色模式。
- 不修改数据库结构。
- 不自动创建 tag、release 或提交。

## 4. 外部参考与取舍

### 4.1 官方规范

- Material 3 Compose：继续作为基础组件和 token 模型来源。参考：<https://developer.android.com/develop/ui/compose/designsystems/material3>
- Android Adaptive Icon：App 图标需要 foreground/background 分层，并补 monochrome icon 支持 Android themed icons。参考：<https://developer.android.com/develop/ui/views/launch/icon_design_adaptive>
- Android Splash Screen：后续补启动图时按官方 splash screen API 处理，不用自绘延迟页。参考：<https://developer.android.com/develop/ui/views/launch/splash-screen>

### 4.2 开源 / 网页审美参考

这些项目不直接引入，只参考信息架构、美学密度和组件组织：

- `vercel/ai-chatbot`：AI 聊天 Web 产品的 thread、composer、model selector、message actions 组织。参考：<https://github.com/vercel/ai-chatbot>
- `shadcn-ui/ui`：中性、低装饰、高一致性的 token 化组件美学。参考：<https://github.com/shadcn-ui/ui>
- `GetStream/stream-chat-android`：聊天 UI 组件层级和 Compose 聊天模式。参考：<https://github.com/GetStream/stream-chat-android>
- `skydoves/chatgpt-android`：Android Compose AI Chat 的 design system 组织方式。参考：<https://github.com/skydoves/chatgpt-android>
- `Taewan-P/gpt_mobile`：移动端多 Provider / 设置体验参考。参考：<https://github.com/Taewan-P/gpt_mobile>

### 4.3 参考结论

- 继续用 Material 3 是正确路径：当前项目已经有主题、Typography、Shapes、Spacing，直接推翻成本高。
- 网页项目可借鉴“干净、中性、低装饰、状态明确”，但不能照搬网页的大屏布局和 hover 行为。
- 聊天产品的视觉重点不是花，而是消息可读性、输入效率、恢复路径、模型状态透明。
- 图片生成需要比聊天更有“作品感”，但不应该喧宾夺主。

## 5. 方案对比

### 方案 A：静谧工作台 / Quiet Workbench（推荐）

一句话：在现有 emerald + Material 3 基础上建立品牌 token、图标资产和轻创作感。

适合原因：

- 与当前 `Workbench` 命名、代码组件和重构方向一致。
- 保留已有绿色识别，迁移成本最低。
- 适合本地优先、多 Provider、工具型 AI App。
- 聊天和图片生成可以通过辅助色、图形母题区分，不需要重写架构。

代价：

- 视觉冲击力不会像紫粉生成艺术平台那么强。
- 需要精细打磨空状态、图标、间距、状态色，否则容易继续显得“只是 Material 组件”。

### 方案 B：生成艺术平台 / Creative Studio

一句话：把图片生成作为主角，使用更大胆的深色、violet、pink、cyan、画布纹理和作品库氛围。

适合原因：

- 图片生成会更有吸引力。
- App 商店截图更容易做出视觉冲击。
- 更接近现代 AI 创作工具。

代价：

- 会弱化“本地优先、Provider 管理、聊天工具”的可信感。
- 可能与当前 emerald 视觉冲突，需要大规模重设颜色和截图。
- 聊天页容易被装饰拖累，可读性风险更高。

### 方案 C：极简系统工具 / Minimal Utility

一句话：几乎去品牌化，只保留黑白灰 + 单一强调色，追求最高信息效率。

适合原因：

- 实现最稳，维护成本最低。
- 对长文本聊天和设置表单友好。
- 暗色模式容易做到高对比。

代价：

- App 图标、启动图、空状态记忆点不足。
- 很难体现图片生成的创作感。
- 与“品牌化”目标不完全匹配。

### 最终选择

采用 **方案 A**，并吸收方案 B 的少量创作色和方案 C 的克制密度。

原则是：聊天像工作台，图片像画布，模型连接像控制台，整体像同一个可信工具。

## 6. 品牌策略

### 6.1 品牌命名

推荐面向用户的名称：

```text
AI 工作台
```

英文内部名：

```text
AI Chat Workbench
```

保留原因：

- 当前 package、组件命名已经大量使用 `workbench`。
- “AI 聊天”太泛，无法覆盖图片生成和模型服务管理。
- “工作台”能表达本地优先、模型连接、聊天、图片生成和后续数据管理。
- 中文用户能快速理解，不需要解释品牌造词。

可选副标题：

```text
本机优先的模型对话与图像创作
```

App 内短描述：

```text
连接你的模型，在本机完成对话和图像创作。
```

### 6.2 品牌人格

品牌人格用四个词约束所有视觉和文案：

| 人格 | 设计含义 | 避免 |
| --- | --- | --- |
| 安静 | 背景中性，动效克制，内容优先 | 大面积渐变、装饰光斑、强烈霓虹 |
| 可信 | 本地保存、密钥安全、状态透明 | 模糊承诺、拟人化夸张语气 |
| 敏捷 | 输入快、配置快、错误可恢复 | 深层嵌套、过多确认、长文案 |
| 有创造力 | 图片生成区域有画布和作品感 | 所有页面都像设置表单 |

### 6.3 品牌叙事

核心叙事：

```text
把分散的模型服务收进一个本机工作台。
```

三个支柱：

- 对话：清晰、可搜索、可恢复。
- 图像：从提示词到作品库的轻创作流程。
- 模型连接：用户自己控制 Provider、API Key、模型角色和请求去向。

### 6.4 文案语气

文案应该像一个可靠工具，不像营销页面。

推荐：

- “连接模型”
- “配置模型连接”
- “本地保存，密钥不进入备份。”
- “生成图片前请先配置支持图片生成的模型服务。”
- “回复生成失败，内容未完成。可重试或检查模型连接。”

避免：

- “释放无限创造力”
- “下一代智能体验”
- “让 AI 改变一切”
- “一键开启未来”

## 7. 图形母题

### 7.1 核心母题

推荐使用 **“对话框 + 星核 + 画框/滑杆”** 三个图形要素，而不是机器人头像。

原因：

- 对话框代表聊天。
- 星核代表 AI 生成和灵感，但比魔法棒更克制。
- 画框代表图片生成。
- 滑杆代表模型连接和参数控制。
- 组合后能覆盖当前产品核心能力。

### 7.2 图形规则

- 线条：统一 2dp stroke，圆端点。
- 转角：图标内角 4dp，外层容器 12-16dp。
- 填充：一级品牌图标可用实心，功能图标优先 outline。
- 星核：最多 3 个点或 1 大 2 小，不做复杂星空。
- 画框：用简化矩形和山形，不用写实图片缩略图。
- 滑杆：只用于模型/设置/调参，不用于聊天主入口。

### 7.3 页面母题映射

| 场景 | 图形母题 | 颜色 |
| --- | --- | --- |
| App 图标 | 对话框 + 星核 + 画框 | Emerald + white |
| 聊天空态 | 星核在对话框中心 | Emerald / mint |
| 图片生成空态 | 画框 + 星核落点 | Cyan / violet 少量 |
| 模型未配置 | 滑杆 + 断点 | Amber |
| Provider 健康 | 滑杆 + check / warning | Emerald / amber / red |
| 数据隐私 | 盾牌 + 本机节点 | Slate / emerald |

## 8. App 图标设计规范

### 8.1 图标目标

App 图标要在启动器中表达三个信息：

- 这是 AI 工具，不是普通聊天。
- 支持聊天和图片。
- 有安静、可信、专业的气质。

### 8.2 推荐图标构图

图标名称：

```text
Workbench Spark
```

构图：

- 背景：圆角方形 adaptive icon background，主色 `Brand Emerald 700`。
- 前景：
  - 一个简化对话框轮廓。
  - 对话框右下嵌入一个小画框。
  - 中心或右上放一个星核。
- 不出现文字、机器人脸、渐变球、过细线条。

示意结构：

```text
+-----------------------+
|       emerald bg       |
|                       |
|     ┌──────────┐      |
|     │    ✦     │      |
|     │       ▱  │      |
|     └───╮──────┘      |
|         ╰             |
|                       |
+-----------------------+
```

### 8.3 Adaptive Icon 资源

建议新增资源：

```text
app/src/main/res/mipmap-anydpi-v26/ic_launcher.xml
app/src/main/res/mipmap-anydpi-v26/ic_launcher_round.xml
app/src/main/res/drawable/ic_launcher_background.xml
app/src/main/res/drawable/ic_launcher_foreground.xml
app/src/main/res/drawable/ic_launcher_monochrome.xml
```

Manifest 后续应显式声明：

```xml
android:icon="@mipmap/ic_launcher"
android:roundIcon="@mipmap/ic_launcher_round"
```

### 8.4 图标尺寸与安全区

按 Android adaptive icon 思路：

- 源文件使用矢量优先，方便主题色和密度适配。
- 前景图形必须留出充足裁切安全区，避免不同 launcher mask 裁掉星核或气泡尾巴。
- 核心符号占前景视觉宽度约 60%-66%。
- 星核不要贴边，保证圆形、圆角方、泪滴等 mask 下都完整。
- monochrome icon 使用单色 path，不依赖背景颜色表达含义。

### 8.5 图标色彩

| 层级 | Light | Dark / Themed |
| --- | --- | --- |
| Background | `#0A8F5C` | 系统 themed icon 由 launcher 着色 |
| Foreground | `#FFFFFF` | monochrome path |
| Detail cut | `#BFF4DA` 可选 | 不用于 monochrome |

### 8.6 禁止项

- 不用 “AI” 两个字母塞进图标。
- 不用 OpenAI 风格旋结，避免品牌混淆。
- 不用真实机器人头像。
- 不用复杂渐变背景。
- 不用过细的 1px 多层线稿。

## 9. 启动图与首屏体验

### 9.1 启动图

启动图保持短、干净，不做假加载。

建议：

- 背景跟随主题：
  - Light：`#F8FAFB`
  - Dark：`#09090B`
- 中心图标：使用 `Workbench Spark` 前景符号。
- 图标容器：
  - Light：`#E6F7EF`
  - Dark：`#0D2818`
- 不显示 slogan，避免启动闪过文字造成跳动。

### 9.2 首屏策略

首次启动仍进入聊天主屏，但空态改为品牌化空态：

标题：

```text
连接模型
```

说明：

```text
添加模型连接后，请求会从本机发送到你的接口。
```

主按钮：

```text
配置模型连接
```

视觉：

- 中心使用星核对话框图形。
- 按钮使用 primary emerald。
- 辅助说明控制在 2 行内。
- 不把“未配置”做成强错误，应视为 onboarding 状态。

## 10. 色彩系统

### 10.1 色彩方向

保留当前 emerald，但加入两个辅助角色：

- Cyan：用于图片生成、作品库、创作状态。
- Amber：用于模型缺失、配置警告、可恢复风险。

比例：

```text
Neutral 70%
Emerald 20%
Cyan / Violet / Amber / Red 10%
```

这样能避免界面被单一绿色统治，也不会变成花哨的 AI 霓虹风。

### 10.2 品牌基础色

| Token | Hex | 用途 |
| --- | --- | --- |
| `brand.emerald.700` | `#0A8F5C` | Light primary、主按钮、品牌核心 |

| `brand.mint.50` | `#E6F7EF` | Light primary container、空态底色 |
| `brand.mint.950` | `#0D2818` | Dark primary container |
| `brand.teal.600` | `#0D9488` | 次级功能、连接健康 |
| `brand.cyan.600` | `#0891B2` | 图片生成、作品库 |

深色模式继续避免纯黑全屏，保持当前 `#09090B`。

### 10.5 语义色规则

- Primary 只表示主要行动、当前选中、品牌。
- Cyan 只表示图片生成、画布、作品库。
- Amber 表示用户可修复的问题，例如未配置模型、模型能力不匹配。
- Red 表示失败、删除、不可逆操作。
- Green 不用于“成功以外的一切”，避免语义稀释。
- 状态必须有文字或图标，不只靠颜色。

## 11. 字体与排版

### 11.1 字体策略

继续使用系统字体栈：

- Android 英文：Roboto / system sans。
- 中文：系统 Noto Sans CJK fallback。
- 不引入第三方字体文件，避免 APK 体积和字重缺失。

### 11.2 排版原则

- 页面标题不再频繁使用 oversized headline，移动端更克制。
- 聊天内容以 `bodyLarge` / `bodyMedium` 为主，不牺牲可读性。
- 设置、Provider、参数行使用 `titleSmall` + `bodySmall`，提高扫描效率。
- 不使用负字距；当前 `letterSpacing = 0.sp` 保留。
- 支持系统字体缩放，不用固定高度截断长中文。

### 11.3 类型角色建议

| 场景 | Typography Role | 字重 | 备注 |
| --- | --- | --- | --- |
| 主页面标题 | `headlineSmall` | SemiBold | 只在页面顶部使用 |
| 顶栏标题 | `titleMedium` | SemiBold | 当前聊天顶栏合理 |
| 分区标题 | `titleSmall` | Medium / SemiBold | 设置和参数区域 |
| 正文消息 | `bodyLarge` | Normal | 长文本阅读 |
| 消息辅助信息 | `bodySmall` | Normal | 状态、时间、模型 |
| 按钮 | `labelLarge` | Medium | 不全大写 |
| 状态 pill | `labelMedium` | Medium | 需要短文本 |

### 11.4 中文文案换行

- 空态说明最多 2 行。
- Provider 名称、模型名默认单行省略；详情页再展开。
- 错误文本先给短摘要，诊断详情放复制按钮或展开区。
- 图片提示词输入框不应被 label 和 helper text 挤压，最小高度保留 128dp。

## 12. 圆角、边框与层级

### 12.1 当前问题

当前 Shapes 中 `extraLarge = 28.dp`，底栏选中态、输入框、按钮容易出现大胶囊感。聊天产品可以保留输入区的柔和，但列表、卡片、设置项需要更稳。

### 12.2 推荐圆角表

| Token | 值 | 用途 |
| --- | --- | --- |
| `radius.xs` | 6dp | 小标签、状态点背景 |
| `radius.sm` | 8dp | 小按钮、小图像缩略图 |
| `radius.md` | 12dp | 列表行容器、Provider row |
| `radius.lg` | 16dp | 消息气泡、表单 panel、图片卡片 |
| `radius.xl` | 22dp | Bottom sheet、dialog |
| `radius.pill` | 999dp | Composer 输入框、segmented chip |

### 12.3 边框规则

- 大多数容器用 1dp outlineVariant，而不是阴影。
- Light 下边框可用 `#E2E8F0` / 56% alpha。
- Dark 下边框可用 `#27272A` / 80% alpha。
- 消息气泡边框要比表单容器更弱，避免聊天列表变成卡片墙。

### 12.4 阴影规则

- 默认不使用明显阴影。
- Dialog / bottom sheet / FAB 可以使用 Material elevation。
- 图片生成结果卡可以使用 1 层柔和 elevation 或边框，不能加多层投影。
- Pressed state 不改变布局尺寸，只用 state layer / alpha / scale 0.98。

## 13. 间距与布局

### 13.1 基线

继续使用 `WorkbenchSpacing`：

```kotlin
xxs = 2.dp
xs = 4.dp
s = 8.dp
m = 12.dp
l = 16.dp
xl = 24.dp
xxl = 32.dp
xxxl = 48.dp
```

### 13.2 页面 gutter

| 屏幕 | 横向 gutter | 说明 |
| --- | --- | --- |
| 手机竖屏 | 16dp | 默认 |
| 手机横屏 | 24dp | 避免贴边 |
| 折叠屏 / 平板单栏 | 24-32dp | 内容最大宽度控制 |
| Two-pane | pane 内 24dp | 参考现有 `TwoPaneLayout` |

### 13.3 垂直节奏

- 顶栏和内容之间不要出现过大空洞。
- 表单内部字段间距 12dp。
- 分区之间 24dp。
- 空态图标到标题 20-24dp。
- 空态标题到说明 8dp。
- 主按钮与说明 20-24dp。

### 13.4 聊天布局

- 消息列表底部必须给 composer 留出 inset。
- Assistant 消息最大宽度在手机上使用 `fillMaxWidth` 减少蛇形换行；在大屏限制 640dp。
- User 消息可右侧 85%-88% 宽度，不建议固定 312dp 导致大屏太窄。
- 系统消息和 error notice 居中或全宽浅色，不与普通消息气泡混淆。

## 14. 图标系统

### 14.1 图标来源

当前 Android Compose 已使用 Material Icons。推荐继续使用同一套，后续如迁移到 Material Symbols，需要一次性统一，不要混用两套风格。

### 14.2 图标尺寸

| 场景 | 图标视觉尺寸 | 触控区域 |
| --- | --- | --- |
| 顶栏操作 | 24dp | 48dp |
| 列表 leading icon | 20-24dp | 行高 56dp+ |
| 状态 pill | 16-18dp | pill 高 28-32dp |
| 空态主图标 | 32-40dp | 容器 72-88dp |
| App 图标前景 | 矢量源 | adaptive mask 安全区 |

### 14.3 图标语义

- `Tune`：模型连接、参数、Provider 设置。
- `Image`：图片生成入口。
- `Chat`：对话入口。
- `Search`：消息搜索。
- `Shield/Security`：本地数据与隐私。
- `Palette`：外观。
- `Info`：关于。
- `AutoAwesome`：AI / 生成空态，但不要到处使用。

### 14.4 禁止项

- 不用 emoji 作为结构图标。
- 不在同一层级混用 filled 和 outlined，除非 selected / unselected 有明确语义。
- icon-only button 必须有 contentDescription，当前 `WorkbenchIconButton` 的方向正确。
- 不用图片 PNG 做可主题化图标。

## 15. 动效系统

### 15.1 原则

- 动效表达因果：发送、停止、生成、展开、切换、错误恢复。
- 不做持续装饰动画。
- 所有动效尊重 reduced motion。
- 触控反馈 80-150ms 内出现。

### 15.2 Timing Tokens

| Token | 时长 | 用途 |
| --- | --- | --- |
| `motion.instant` | 80-120ms | pressed / state layer |
| `motion.fast` | 150ms | icon / chip 状态 |
| `motion.standard` | 200-240ms | sheet 内容、列表 item |
| `motion.slow` | 280-320ms | 页面级进入、空态出现 |
| `motion.exit` | 120-180ms | 关闭、退出，比进入快 |

### 15.3 Spring Tokens

保留现有 `smooth`，降低 `bouncy` 使用范围：

- `smooth`：sheet、展开、列表更新。
- `lowBounce`：图片生成完成、作品卡出现。
- `bouncy`：只给发送按钮或成功反馈，不给所有卡片。

### 15.4 重点动效

- 发送按钮：从箭头到停止生成，使用 crossfade 或 icon swap，避免布局跳动。
- 图片生成：生成中显示进度占位 / skeleton，不要空白等待。
- 模型连接测试：按钮内 spinner + 文案“测试中”，完成后 inline notice。
- Bottom sheet：从底部进入，scrim 稳定，不出现黑色闪烁。
- 会话抽屉：保留 Material drawer 行为，选中项使用轻 tonal background。

## 16. 核心组件改版规范

### 16.1 App Shell

目标：

- App 第一屏是聊天，而不是营销首页。
- 会话历史通过抽屉进入。
- 设置和图片生成从顶栏更多菜单 / 设置页进入。

规范：

- 顶栏背景使用 `surface` 或 `background`，不混用。
- 顶栏标题最多 1 行，副标题最多 1 行。
- 顶栏操作最多显示 2 个直接 icon，其余进更多菜单。
- 若 Provider 未配置，副标题显示“需要模型连接”，不显示技术错误。

### 16.2 聊天消息

Assistant 消息：

- 背景：`surfaceContainerLow`
- 边框：`outlineVariant` 35%-56%
- 圆角：16dp
- 左对齐，内容最大宽度按窗口自适应。
- 操作按钮默认弱化，长按/更多入口可见。

User 消息：

- 背景：`primaryContainer`
- 文字：`onPrimaryContainer`
- 右对齐。
- 圆角：16dp，尾部可不做复杂气泡尖角。

System / Notice：

- 不使用聊天气泡样式。
- 使用 inline notice 或 compact strip。
- 图标 + 文案 + 操作按钮结构。

### 16.3 Composer 输入栏

当前输入栏是品牌体验核心，建议重点打磨：

- 容器背景：`surface`，底部使用 navigation bar padding。
- 输入框：pill 或 20-24dp 圆角，但只在 composer 使用。
- 左侧：图片附件按钮，未启用模型时仍可打开选择，但发送前确认。
- 右侧：发送 / 停止按钮，48dp 触控区域。
- 错误状态：输入栏上方 inline notice，不覆盖输入。
- 多图草稿：缩略图横排，移除按钮 32-40dp 触控区域。

### 16.4 会话抽屉

目标：

- 把会话历史变成“工作台侧栏”，不是普通列表。

规范：

- 顶部：品牌小图标 + “AI 工作台”。
- 新建会话：primary tonal button。
- 会话项：
  - 标题 1 行。
  - 预览 1-2 行。
  - 时间或消息数量弱显示。
  - 当前会话用 mint background + emerald leading indicator。
- 底部：设置、图片生成、数据与隐私入口。

### 16.5 图片生成页

目标：

- 从“表单”升级为“图像创作台”，但不牺牲输入效率。

规范：

- 页面标题可保留“图片生成”，但 panel 标题建议“图像创作台”。
- 图片生成相关 accent 使用 cyan，不与聊天 primary 完全一样。
- 提示词输入框保留大面积，但边框更弱，聚焦时 cyan / emerald 二选一：
  - 如果作为全局表单：emerald。
  - 如果作为图片专属创作：cyan。
- 参数摘要保留折叠。
- 作品库：
  - 空态使用画框 + 星核，不复用聊天空态。
  - 生成结果使用固定 aspect ratio 卡片。
  - 操作：复用提示词、重新生成、保存、分享、带入聊天。
  - 图片缩略图加载失败要有可恢复占位。

### 16.6 Provider 设置页

目标：

- 让模型连接像“控制台”，但文案仍是普通用户能懂的。

规范：

- 顶部健康区：
  - 有可用聊天模型。
  - 有可用图片模型。
  - API Key 本地保存。
  - 最近测试状态。
- Provider row：
  - 名称、类型、模型摘要、启用状态。
  - 文本模型和图片模型用小 pill 标识。
  - 删除动作不要常驻红色，只在操作 sheet 或确认对话中出现。
- 编辑 sheet：
  - 分组：基础信息 / 认证 / 模型角色 / 高级请求。
  - 默认只展开基础信息和认证。
  - Headers、HTTP 开关等高级项折叠。

### 16.7 设置页

目标：

- 设置页是二级入口索引，不承担所有配置。

规范：

- 每项使用 icon + title + description + chevron。
- Disabled 项不要像失败状态，使用 38%-42% alpha。
- “外观”后续承载：
  - 跟随系统 / 浅色 / 深色。
  - 动态颜色开关，如果后续支持 Material You。
  - 显示密度：舒适 / 紧凑。
  - 消息宽度：默认 / 宽屏。

## 17. 空状态与错误状态

### 17.1 空状态类型

| 状态 | 标题 | 说明 | 主操作 | 图形 |
| --- | --- | --- | --- | --- |
| 未配置模型 | 连接模型 | 添加模型连接后，请求会从本机发送到你的接口。 | 配置模型连接 | 星核对话框 |
| 无会话 | 开始新对话 | 输入问题，或先选择一个模型连接。 | 新对话 | 对话框 |
| 图片无历史 | 暂无作品 | 输入提示词生成第一张图片。 | 无或聚焦输入 | 画框星核 |
| 无搜索结果 | 没找到匹配 | 换个关键词试试。 | 清空搜索 | 放大镜 |
| Provider 为空 | 添加模型连接 | 支持 OpenAI 和兼容接口。 | 添加模型连接 | 滑杆 |

### 17.2 错误状态

错误文案结构：

```text
发生了什么 + 用户能做什么
```

示例：

- “回复生成失败，内容未完成。请重试或检查模型连接。”
- “图片生成失败：当前模型不支持图片生成。请切换图片模型。”
- “连接测试失败：接口返回 401。请检查 API Key。”

错误 UI：

- 可恢复错误：inline notice + 重试 / 配置 / 复制诊断。
- 不可逆操作：确认 dialog + red confirm。
- 长诊断：不直接展开占屏，用“复制诊断”或二级详情。

## 19. Material Theme 重构建议

### 19.1 文件结构

建议后续把当前 `Theme.kt` 拆得更清楚：

```text
ui/theme/
├── BrandColors.kt
├── ColorScheme.kt
├── Typography.kt
├── Shapes.kt
├── Spacing.kt
├── Motion.kt
├── BrandAssets.kt
└── Theme.kt
```

拆分目标：

- `BrandColors.kt`：品牌基础色和语义扩展色。
- `ColorScheme.kt`：Material light/dark scheme 映射。
- `Typography.kt`：当前 AppTypography。
- `Shapes.kt`：圆角 token。
- `BrandAssets.kt`：Compose vector / brand mark 入口，如果采用代码绘制。

### 19.2 语义扩展 token

Material `ColorScheme` 不够表达所有业务语义，建议新增：

```kotlin
data class WorkbenchSemanticColors(
    val success: Color,
    val onSuccess: Color,
    val successContainer: Color,
    val warning: Color,
    val onWarning: Color,
    val warningContainer: Color,
    val imageAccent: Color,
    val onImageAccent: Color,
    val imageAccentContainer: Color,
    val privacyAccent: Color,
)
```

使用方式：

- Material `colorScheme` 负责基础 UI。
- `WorkbenchSemanticColors` 负责业务状态和图片创作场景。
- 组件不直接写 raw hex。

### 19.3 Component Tokens

建议为关键组件定义固定 token：

```text
message.assistant.container
message.assistant.border
message.user.container
composer.container
composer.input
notice.warning.container
provider.healthy.container
image.canvas.container
image.result.border
```

这些 token 可以先用函数或 object 表达，不急于做复杂 DesignSystem 类。

- 是否 App 图标在 launcher mask 下仍清晰？

## 22. 风险与取舍

### 22.1 品牌名风险

把 `AI 聊天` 改为 `AI 工作台` 会影响用户认知和 Release 展示。

建议：

- 若当前用户规模小，直接改名。
- 若已有用户习惯，App 名可先保留 `AI 聊天`，在 About / README / 截图中使用 `AI 工作台` 作为产品线名。

### 22.2 色彩风险

增加 cyan/violet 可能破坏当前 emerald 的一致性。

控制方式：

- Cyan 只给图片生成。
- Violet 只给创作增强态，默认不出现在聊天主流程。
- 所有语义色进入 token，不让业务组件自由选色。

### 22.3 圆角调整风险

降低圆角会改变现有截图观感。

控制方式：

- Composer 和主按钮保留柔和。
- 列表、卡片、Provider row 先降到 12-16dp。
- 不一次性把所有圆角改成硬矩形。

### 22.4 图标资产风险

矢量图标如果一次画得太复杂，在小尺寸 launcher 中会糊。

控制方式：

- 先做黑白单色可读性测试。
- 再加背景色。
- 最后做 adaptive mask 测试。

### 22.5 工作量风险

品牌化容易膨胀成全量 UI 重写。

控制方式：

- 阶段 1-3 只做 token、图标和空态。
- 阶段 4-6 再按页面逐步改。
- 不改业务逻辑，不改数据库。

## 25. 成功标准

改版完成后应满足：

- 启动器中能识别出独立品牌，不再使用默认图标。
- 首屏未配置模型状态像引导，不像报错。
- 聊天、图片生成、Provider 设置共享同一色彩、圆角、图标和文案规则。
- 图片生成有独立创作气质，但不破坏整体安静工作台风格。
- 深色模式不是简单反色，文字、边框、状态都清楚。
- 所有主要操作触控区域不小于 48dp。
- `lint assembleDebug` 通过；涉及逻辑改动时 `testDebugUnitTest` 通过。
