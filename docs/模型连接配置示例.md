# Provider 配置示例

## 目标

支持三类 OpenAI 兼容入口：

- `newapi`
- `sub2api`
- `custom`

它们都复用 OpenAI Chat Completions / Images 兼容协议。Base URL 来自 App 内 Provider 配置；如果配置为根地址，例如 `https://zzshu.cc`，请求会自动补齐到 `/v1`。

## App 内配置

### New API

```text
类型：New API
接口地址：https://your-newapi.example.com
API Key：在 App 内输入并保存到 Android Keystore
默认模型：按服务端实际模型填写
```

### Sub2 API

```text
类型：Sub2 API
接口地址：https://your-sub2api.example.com
API Key：在 App 内输入并保存到 Android Keystore
默认模型：按服务端实际模型填写
```

### 自定义兼容接口

```text
类型：自定义兼容接口
接口地址：https://zzshu.cc
API Key：不要写入代码；通过 App 表单、环境变量或 GitHub Secrets 提供
默认模型：gpt-image-1 或服务端实际支持的模型
```

New API、Sub2 API 和自定义兼容接口没有内置默认接口地址。新建连接时切换到这些类型，表单会清空接口地址，避免误用 OpenAI 默认地址。

## 图片生成路径

当 Base URL 为：

```text
https://zzshu.cc
```

图片生成请求路径为：

```text
https://zzshu.cc/v1/images/generations
```

当 Base URL 已经包含 `/v1`：

```text
https://zzshu.cc/v1
```

图片生成请求路径保持：

```text
https://zzshu.cc/v1/images/generations
```

## Secrets

本仓库不硬编码 API Key。CI 或脚本需要连接外部 Provider 时使用：

```text
AI_CHAT_PROVIDER_BASE_URL=https://zzshu.cc
AI_CHAT_PROVIDER_API_KEY=replace-with-your-secret
```

GitHub Actions 中配置同名 Secrets：

```text
AI_CHAT_PROVIDER_BASE_URL
AI_CHAT_PROVIDER_API_KEY
GATEWAY_API_TOKEN
```

当前 CI 只执行 lint、单元测试和构建，不主动请求外部 Provider。需要做真实 Provider 冒烟测试时，再新增显式 workflow step，并从这些 Secrets 读取配置。

`.env.example` 只保留占位符，不存放真实密钥。
