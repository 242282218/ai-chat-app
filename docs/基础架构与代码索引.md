# 基础架构与代码索引

本文对应当前 Android 原生 AI 聊天工作台代码状态，用于快速定位项目目录、架构分层、核心模型、网络封装和主要页面入口。

## 架构设计

当前 Android App 使用单模块原生架构，边界按 `feature -> domain -> data/provider/tool` 组织：

- `feature` 层只处理 UI 状态、用户动作和 Compose 视图。页面入口包括 `HomeScreen`、`ChatScreen`、`ImageGenerationScreen`、`SettingsHubScreen`。
- `domain` 层定义纯业务模型、Repository 接口和 UseCase，避免把 Room entity 或网络 DTO 泄漏到 UI。
- `data` 层负责本地持久化。Room 保存会话、消息、Provider、Prompt、模型角色偏好、工具结果和图片历史；DataStore 保存图片生成偏好和主题模式；API Key 通过 `SecretStore` 存放。
- `provider` 层负责模型服务网络请求。文本对话仍复用 OkHttp/SSE；图片生成已通过 Retrofit 调用 OpenAI-compatible 图片接口。
- `tool` 层负责本地工具和可选 Gateway 工具，聊天生成控制器通过 `ToolExecutor` 编排工具调用结果。
- `app/AppModule.kt` 是主要依赖注入入口，统一注册数据库、Repository、网络 client、Provider、工具执行器和 ViewModel。

主导航是四个底部 Tab：对话、工具、图片、设置。聊天详情页是 push screen，避免在 Tab 中复制聊天状态。

## 核心数据模型

主要领域模型位置：

- `domain/model/Conversation.kt`：会话、模型参数、临时会话和敏感会话标记。
- `domain/model/Message.kt`：消息角色、状态、多模态 `MessagePart`、工具调用和工具结果引用。
- `domain/model/ProviderConfig.kt`：Provider 类型、Base URL、模型列表、模型能力和协议描述。
- `domain/model/ImageGeneration.kt`：图片生成请求历史、模型、尺寸、质量、文件路径和状态。
- `domain/model/ToolResult.kt`：工具权限级别、状态、输入输出 JSON、错误和耗时。
- `domain/model/ThemeMode.kt`：主题模式，支持跟随系统、浅色和深色。
- `domain/model/Ids.kt`：强类型 ID，避免跨表和跨模块传错字符串。

Room 数据库入口是 `data/local/AiChatDatabase.kt`，当前 schema version 为 10。修改 Room entity/DAO/Database 时必须同步 migration、schema JSON 和迁移测试。

## 网络层封装

网络 client 统一在 `provider/http/WorkbenchHttpClients.kt` 创建：

- `json()`：普通 JSON 请求，适合模型发现、连接测试、Gateway JSON API。
- `streaming()`：长读超时，用于聊天流式响应。
- `longRunning()`：用于图片生成等长耗时请求。

文本 Provider：

- `provider/openai/OpenAiChatProvider.kt`：OpenAI Responses / Chat Completions 兼容实现。
- `provider/compatible/OpenAiCompatibleChatProvider.kt`：OpenAI-compatible provider，使用 Chat Completions 协议。
- `provider/api/ProviderEndpoint.kt`：把可配置 Base URL 规范化到 OpenAI-compatible `/v1`。

图片 Provider：

- `provider/image/OpenAiImageGenerationProvider.kt` 使用 Retrofit + kotlinx.serialization 调用 `images/generations`。
- endpoint 由 `ProviderConfig.baseUrl` 规范化后拼接，实际接口为 `/v1/images/generations`。
- API Key 从安全存储读取后通过 `Authorization: Bearer <key>` 传入，不写入源码、文档或测试 fixture。
- `IMAGE_API_KEY` 不是独立硬编码字段，而是保存到独立图片 Provider 的 API Key；图片页通过 `DataStoreImageGenerationPreferencesRepository` 记住默认图片 Provider 和模型。
- Provider 返回 URL 时，会下载图片并转为 base64 交给本地图片存储。

配置占位：

```text
API_BASE_URL={{API_BASE_URL}}
API_KEY={{API_KEY}}
IMAGE_API_KEY={{IMAGE_API_KEY}}
endpoint=/v1/images/generations
```

推荐配置方式：

- 聊天 Provider：使用 `API_BASE_URL` 和 `API_KEY`。
- 图片 Provider：可单独新建 New API 或自定义兼容接口 Provider，Base URL 同样使用 `API_BASE_URL`，API Key 填 `IMAGE_API_KEY`。
- 如果聊天和图片使用同一个服务，也可以复用同一个 Provider；如果密钥不同，应拆成两个 Provider。

## 存储层

Room：

- `RoomConversationRepository`：会话、消息、FTS 搜索。
- `RoomProviderConfigRepository`：Provider 和 API Key 引用。
- `RoomImageGenerationRepository`：图片生成历史。
- `RoomToolInvocationRepository`：工具运行历史。
- `RoomModelRolePreferenceRepository`：对话、图片、工具、代码等模型角色偏好。

DataStore：

- `DataStoreImageGenerationPreferencesRepository`：保存图片生成默认 Provider 和模型，并从旧 SharedPreferences 自动迁移。
- `DataStoreThemeSettingsRepository`：保存主题模式，系统模式不写持久值。

安全：

- `AndroidSecretStore` 封装 Android Keystore 支持的本地密钥存储。
- 备份导出不会包含 API Key。

首页：

- `feature/home/HomeScreen.kt`
- `feature/home/HomeViewModel.kt`
- 展示任务输入、最近会话、本地消息搜索、快速入口和 Provider 配置提醒。

- `feature/chat/ChatViewModel.kt`

- `feature/settings/SettingsHubScreen.kt`

工具中心：

- `feature/tools/ToolsScreen.kt`

## 可运行验证

Android 最小验证命令：

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:lint :app:assembleDebug --no-daemon --stacktrace
```

当前本机访问 Google Maven 可能出现 TLS 握手问题。若只是本机网络问题，可临时使用 Gradle init 脚本切换到可达镜像验证；不要把镜像配置写入仓库，CI 仍使用 `settings.gradle.kts` 的官方仓库配置。

Gateway 验证：

```powershell
cd gateway
go test ./...
```

## 当前边界

- App 已是 Kotlin + Compose + ViewModel + Coroutines + Room + DataStore + Retrofit 的原生实现。
- 图片生成接口可通过 Provider 配置接入 OpenAI-compatible `/v1/images/generations`。
- 测试 API Key 只能通过安全存储、环境变量或手动设置输入；禁止写入源码和文档。
- Gateway 是可选增强，不是移动端第一路径依赖。
