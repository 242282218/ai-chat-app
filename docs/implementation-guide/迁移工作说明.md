## 🔍 关键设计决策

### 1. 数据流架构
```
Room Database (唯一数据源)
       ↓
MessageConverter (转换层)
       ↓
Stream Message (内存，仅展示)
       ↓
Stream UI Components
```

**原因**: Room 作为唯一数据源，避免双向同步的复杂性。

### 2. 并行实现
现有 `feature/chat/` 完全未修改，Stream 实现在 `stream/` 下。

**原因**: 零风险实验，随时可以回滚。

### 3. 渐进式迁移
Phase 3 分步替换：消息列表 → 输入框 → 顶部栏。

**原因**: 每一步可验证、可回滚。
