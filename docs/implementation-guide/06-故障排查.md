## 依赖问题

### ❌ Gradle Sync 失败：找不到 Stream SDK

**症状**:
```
Could not find io.getstream:stream-chat-android-compose:6.5.1
```

**原因**: Maven 仓库配置问题或网络问题

**解决方案**:

1. 检查 `settings.gradle.kts` 中是否包含 Maven Central：
```kotlin
dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral() // 确保有这一行
    }
}
```

2. 清理缓存并重试：
```bash
./gradlew clean --refresh-dependencies
```

3. 如果网络问题，配置代理或等待网络恢复

---

### ❌ 依赖冲突：重复的类

**症状**:
```
Duplicate class io.getstream.chat.android.xxx found in modules
```

**原因**: 同时依赖了多个 Stream SDK 模块，或版本不一致

**解决方案**:

1. 检查 `libs.versions.toml` 中所有 Stream 依赖使用同一个版本号：
```toml
[versions]
streamChatSDK = "6.5.1"  # 确保只有一个版本

[libraries]
stream-client = { group = "io.getstream", name = "stream-chat-android-client", version.ref = "streamChatSDK" }
stream-offline = { group = "io.getstream", name = "stream-chat-android-offline", version.ref = "streamChatSDK" }
stream-compose = { group = "io.getstream", name = "stream-chat-android-compose", version.ref = "streamChatSDK" }
```

2. 运行依赖树分析：
```bash
./gradlew app:dependencies > dependencies.txt
# 查找冲突
```

3. 必要时排除重复依赖：
```kotlin
implementation(libs.stream.compose) {
    exclude(group = "io.getstream", module = "stream-chat-android-ui-common")
}
```

## 初始化问题

### ❌ ChatClient 未初始化

**症状**:
```
java.lang.IllegalStateException: ChatClient.instance() was called before initialize()
```

**原因**: 在调用 `ChatClient.instance()` 前没有初始化

**解决方案**:

1. 确认 `StreamChatInitializer.initialize()` 在 `Application.onCreate()` 中调用：
```kotlin
class WorkbenchApp : Application() {
    override fun onCreate() {
        super.onCreate()
        StreamChatInitializer.initialize(this)
        // ... 其他初始化
    }
}
```

2. 如果使用延迟初始化，确保在首次使用前调用：
```kotlin
class ChatViewModel : ViewModel() {
    init {
        StreamChatInitializer.ensureInitialized(context)
    }
}
```

### ❌ 用户连接失败

**症状**:
```
StreamChatInitializer: Failed to connect user: Invalid token
```

**原因**: Token 生成或验证失败

**解决方案**:

1. 开发环境使用 `devToken`：
```kotlin
val token = chatClient.devToken(user.id)
chatClient.connectUser(user, token).enqueue()
```

2. 检查用户 ID 格式是否正确（不能为空，不能有特殊字符）

3. 确认没有开启服务器端认证（开发模式应该关闭）

## UI 渲染问题

### ❌ MessageList 不显示消息

**症状**: MessageList 组件渲染了，但消息列表为空

**可能原因**:
1. Channel 没有正确创建
2. 消息没有同步到 Stream
3. ViewModel 没有正确初始化

**排查步骤**:

1. 添加日志检查 Channel 状态：
```kotlin
LaunchedEffect(Unit) {
    val channel = messageListViewModel.channel
    Log.d("Debug", "Channel ID: ${channel.id}")
    Log.d("Debug", "Channel messages: ${channel.messages.value.size}")
}
```

2. 检查消息转换是否正确：
```kotlin
val streamMessage = MessageConverter.toStreamMessage(domainMessage, ...)
Log.d("Debug", "Converted message: ${streamMessage.text}")
```

3. 验证 MessagesViewModelFactory 的 channelId 格式：
```kotlin
// 正确格式: "messaging:conversation_xxx"
val channelId = "messaging:conversation_${conversationId.value}"
```

### ❌ 消息显示错位（用户消息显示在左侧）

**症状**: 用户消息应该在右侧，但显示在左侧

**原因**: `isOwnMessage` 判断错误

**解决方案**:

修改 `MessageConverter.toStreamMessage()`：
```kotlin
fun toStreamMessage(
    domainMessage: Message,
    currentUser: User,
    isOwnMessage: Boolean  // 确保这个参数正确传递
): StreamMessage {
    return StreamMessage(
        id = domainMessage.id.value,
        text = domainMessage.content,
        user = if (isOwnMessage) {
            currentUser  // 用户消息用 currentUser
        } else {
            createAiUser()  // AI 消息用 AI 用户
        },
        // ...
    )
}
```

调用时确保正确判断：
```kotlin
val isOwnMessage = domainMessage.role == Message.Role.USER
MessageConverter.toStreamMessage(domainMessage, currentUser, isOwnMessage)
```

### ❌ Markdown 不渲染

**症状**: 消息中的 Markdown 语法显示为纯文本

**原因**: Stream 的 Markdown 渲染可能需要配置

**解决方案**:

1. 检查 Stream SDK 版本是否支持 Markdown

2. 使用自定义消息渲染器：
```kotlin
MessageList(
    itemContent = { messageListItemState ->
        when (messageListItemState) {
            is MessageItemState -> {
                CustomMessageContent(
                    message = messageListItemState.message,
                    enableMarkdown = true
                )
            }
            else -> {
                // 默认渲染
            }
        }
    }
)
```

3. 或使用第三方 Markdown 库（如 `commonmark`）

### ❌ 流式响应不工作

**症状**: AI 响应一次性显示，没有打字机效果

**可能原因**:
1. 消息更新逻辑未实现
2. 更新太快或太慢
3. Channel 消息未正确更新

**解决方案**:

实现正确的流式更新逻辑：
```kotlin
private suspend fun streamAiResponse(
    channelId: String,
    messageId: String,
    fullResponse: String
) {
    val channel = ChatClient.instance().channel(channelId)
    
    // 创建初始消息
    val initialMessage = Message(
        id = messageId,
        text = "",
        user = createAiUser()
    )
    
    // 发送初始消息
    channel.sendMessage(initialMessage).await()
    
    var currentText = ""
    
    // 逐字符更新
    fullResponse.forEach { char ->
        currentText += char
        
        // 更新消息
        val updatedMessage = initialMessage.copy(text = currentText)
        channel.updateMessage(updatedMessage).await()
        
        delay(30) // 控制速度
    }
}
```

调试：
```kotlin
Log.d("Streaming", "Current text length: ${currentText.length}")
```

## 数据同步问题

### ❌ Room 和 Stream 数据不一致

**症状**: Room 中有消息，但 Stream UI 不显示；或反之

**原因**: 数据同步逻辑有问题

**排查步骤**:

1. 确认同步方向：
   - Room 是主数据源
   - Stream 是 UI 展示层
   - 同步应该是 Room → Stream

2. 检查同步触发时机：
```kotlin
LaunchedEffect(conversationId) {
    // 监听 Room 数据变化
    messageRepository.getMessages(conversationId).collect { messages ->
        Log.d("Sync", "Room messages count: ${messages.size}")
        syncToStream(messages)
    }
}
```

3. 验证消息 ID 唯一性：
```kotlin
// Room 和 Stream 使用同一个 ID
val messageId = UUID.randomUUID().toString()
```

4. 添加同步状态日志：
```kotlin
fun syncToStream(messages: List<Message>) {
    Log.d("Sync", "Syncing ${messages.size} messages to Stream")
    messages.forEach { msg ->
        Log.d("Sync", "Syncing message: ${msg.id.value}")
        // ... 同步逻辑
    }
}
```

### ❌ 消息重复显示

**症状**: 同一条消息在列表中显示多次

**原因**: 
1. 消息 ID 不唯一
2. 重复同步
3. Channel 中有重复消息

**解决方案**:

1. 确保消息 ID 全局唯一：
```kotlin
// 使用 UUID
val messageId = UUID.randomUUID().toString()

// 或使用时间戳 + 随机数
val messageId = "${System.currentTimeMillis()}_${Random.nextInt()}"
```

2. 同步前检查消息是否已存在：
```kotlin
suspend fun syncMessageToStream(message: Message) {
    val channel = chatClient.channel(channelId)
    val existingMessages = channel.messages.value
    
    // 检查是否已存在
    if (existingMessages.any { it.id == message.id.value }) {
        Log.d("Sync", "Message ${message.id.value} already exists, skipping")
        return
    }
    
    // 发送新消息
    val streamMessage = MessageConverter.toStreamMessage(message, ...)
    channel.sendMessage(streamMessage).await()
}
```

3. 清理 Channel 中的重复消息（最后手段）：
```kotlin
suspend fun cleanupDuplicates(channelId: String) {
    val channel = chatClient.channel(channelId)
    val messages = channel.messages.value
    val seen = mutableSetOf<String>()
    
    messages.forEach { message ->
        if (message.id in seen) {
            // 删除重复消息
            channel.deleteMessage(message.id).await()
        } else {
            seen.add(message.id)
        }
    }
}
```

## 性能问题

### ❌ 滚动卡顿

**症状**: 消息列表滚动时卡顿，FPS 低于 50

**排查步骤**:

1. 使用 Android Studio Profiler 检查：
   - CPU 占用是否过高
   - 是否有大量 GC
   - 是否有主线程阻塞

2. 检查消息数量：
```kotlin
Log.d("Performance", "Message count: ${messages.size}")
```

**优化方案**:

1. 限制 MessageList 加载数量：
```kotlin
val factory = MessagesViewModelFactory(
    context = context,
    channelId = channelId,
    messageLimit = 30  // 减少初始加载数量
)
```

2. 启用分页加载（Stream 默认支持）

3. 优化自定义消息组件（如果有）：
```kotlin
@Composable
fun CustomMessageItem(message: Message) {
    // 使用 key 优化重组
    key(message.id) {
        // 使用 remember 缓存计算结果
        val formattedText = remember(message.text) {
            formatMarkdown(message.text)
        }
        
        Text(formattedText)
    }
}
```

### ❌ 内存泄漏

**症状**: 应用使用时间越长，内存占用越高，最终 OOM

**排查**:

使用 Android Studio Memory Profiler：
1. 运行应用
2. 进行一些操作（发送消息、切换会话）
3. 手动触发 GC
4. 查看 Heap Dump，寻找异常对象

**常见原因和解决**:

1. ViewModel 未正确清理：
```kotlin
class ChatViewModel : ViewModel() {
    private val job = SupervisorJob()
    private val scope = CoroutineScope(Dispatchers.Main + job)
    
    override fun onCleared() {
        super.onCleared()
        job.cancel()  // 确保取消所有协程
    }
}
```

2. Flow 未取消：
```kotlin
// 使用 lifecycle-aware collect
messageRepository.getMessages(conversationId)
    .flowWithLifecycle(lifecycle)
    .collect { messages ->
        // ...
    }
```

3. ChatClient 持有大量消息：
```kotlin
// 定期清理旧消息
suspend fun cleanupOldMessages(channelId: String, keepCount: Int = 100) {
    val channel = chatClient.channel(channelId)
    val messages = channel.messages.value
    
    if (messages.size > keepCount) {
        val toDelete = messages.take(messages.size - keepCount)
        toDelete.forEach { message ->
            channel.deleteMessage(message.id).await()
        }
    }
}
```

### ❌ 启动时间过长

**症状**: 应用启动时间超过 3 秒

**原因**: Stream SDK 初始化耗时

**优化方案**:

1. 使用延迟初始化（见 Phase 4）

2. 在后台线程初始化：
```kotlin
class WorkbenchApp : Application() {
    override fun onCreate() {
        super.onCreate()
        
        // 其他初始化...
        
        // 异步初始化 Stream SDK
        GlobalScope.launch(Dispatchers.IO) {
            StreamChatInitializer.initialize(this@WorkbenchApp)
        }
    }
}
```

3. 测量启动时间：
```bash
adb shell am start -W com.aichat.workbench/.MainActivity
```

## 编译和构建问题

### ❌ ProGuard 导致运行时崩溃

**症状**: Release 版本崩溃，Debug 正常

**原因**: ProGuard 混淆了 Stream SDK 的类

**解决方案**:

在 `proguard-rules.pro` 中添加保留规则：
```proguard
# 流式聊天实验
-keep class io.getstream.chat.** { *; }
-keep class io.getstream.log.** { *; }
-keep class io.getstream.result.** { *; }
-dontwarn io.getstream.**

# Stream 的模型类
-keepclassmembers class io.getstream.chat.android.models.** {
    <fields>;
    <init>(...);
}

# Kotlin 序列化
-keepattributes *Annotation*, InnerClasses
-dontnote kotlinx.serialization.AnnotationsKt

# Compose
-keep class androidx.compose.** { *; }
-dontwarn androidx.compose.**
```

测试 Release 版本：
```bash
./gradlew assembleRelease
adb install app/build/outputs/apk/release/app-release.apk
```

### ❌ APK 体积过大

**症状**: APK 体积增加超过 5MB

**分析**:

使用 APK Analyzer：
```
Android Studio -> Build -> Analyze APK
```

查看各部分大小，特别是：
- `lib/` 目录（native 库）
- `classes.dex`（代码）
- `res/` 目录（资源）

**优化方案**:

1. 启用资源缩减：
```kotlin
buildTypes {
    release {
        isMinifyEnabled = true
        isShrinkResources = true  // 确保开启
    }
}
```

2. 使用 APK 分割（按 ABI）：
```kotlin
android {
    splits {
        abi {
            isEnable = true
            reset()
            include("armeabi-v7a", "arm64-v8a", "x86", "x86_64")
            isUniversalApk = false
        }
    }
}
```

3. 排除未使用的 native 库：
```kotlin
android {
    packagingOptions {
        exclude("lib/mips/**")
        exclude("lib/mips64/**")
    }
}
```
