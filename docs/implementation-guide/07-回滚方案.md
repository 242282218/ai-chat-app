# 回滚方案

如果在任何阶段遇到无法解决的严重问题，可以按照本文档回滚到之前的状态。

## 🚨 何时考虑回滚

### 必须回滚的情况

- ❌ **严重崩溃**: Release 版本频繁崩溃，无法修复
- ❌ **性能严重下降**: APK 体积增加 > 5MB，或启动时间增加 > 500ms
- ❌ **数据丢失风险**: 发现数据同步问题可能导致消息丢失
- ❌ **不可修复的兼容性问题**: 某些设备或 Android 版本无法运行

### 应该调整方案而非回滚

- ⚠️ **轻微性能问题**: 可以优化
- ⚠️ **UI 不完美**: 可以调整
- ⚠️ **某个功能缺失**: 可以补充实现
- ⚠️ **学习曲线**: 需要时间熟悉

## 回滚策略

根据当前所处的 Phase，选择对应的回滚策略。

---

## Phase 1 回滚

**情况**: 依赖配置阶段遇到无法解决的问题

**影响**: 最小，只添加了依赖，未修改代码

### 回滚步骤

#### 1. 删除分支

```bash
# 确保在 main 分支
git checkout main

# 删除本地分支
git branch -D feature/stream-chat-ui

# 删除远程分支（如果已推送）
git push origin --delete feature/stream-chat-ui
```

#### 2. 恢复文件

如果已经修改了某些文件：

```bash
# 恢复 libs.versions.toml
git checkout main -- gradle/libs.versions.toml

# 恢复 build.gradle.kts
git checkout main -- app/build.gradle.kts

# 删除新创建的文件
rm -rf app/src/main/java/com/aichat/workbench/stream/
```

#### 3. 清理缓存

```bash
./gradlew clean
```

#### 4. 验证

```bash
./gradlew assembleDebug
# 确保构建成功
```

## Phase 2A/2B 回滚

**情况**: 并行开发或验证阶段发现严重问题

**影响**: 中等，创建了新文件，但未修改现有功能

### 回滚步骤

#### 1. 删除新文件

```bash
# 删除 Stream 相关目录
rm -rf app/src/main/java/com/aichat/workbench/stream/

# 删除测试文件（如果创建了）
rm -rf app/src/debug/java/com/aichat/workbench/stream/
```

#### 2. 恢复依赖配置

```bash
# 方法 A: 使用 Git 恢复
git checkout main -- gradle/libs.versions.toml
git checkout main -- app/build.gradle.kts

# 方法 B: 手动删除
# 打开 libs.versions.toml，删除 Stream 相关行
# 打开 build.gradle.kts，删除 Stream 依赖
```

#### 3. 清理 Koin 配置

打开 `app/src/main/java/com/aichat/workbench/app/AppModule.kt`，删除：

```kotlin
// 删除这些行
import com.aichat.workbench.stream.chat.StreamChatViewModel
import com.aichat.workbench.stream.repository.StreamChatRepository
import io.getstream.chat.android.client.ChatClient

// 删除这些定义
single { ChatClient.instance() }
single { StreamChatRepository(get()) }
viewModel { StreamChatViewModel(get(), get(), get()) }
```

#### 4. 删除初始化调用

打开 `AppModule.kt`，删除：

```kotlin
// 删除这一行
StreamChatInitializer.initialize(this)
```

#### 5. Gradle Sync 和构建

```bash
# 同步
./gradlew clean

# 构建
./gradlew assembleDebug
```

#### 6. 验证应用

运行应用，确保所有现有功能正常工作。

## Phase 3 回滚

**情况**: 组件迁移阶段遇到严重问题，现有功能受影响

**影响**: 高，已修改核心文件

### 快速回滚（推荐）

使用 Git 回退到 Phase 2B 结束时的提交：

```bash
# 查看提交历史
git log --oneline

# 找到 Phase 2B 的提交（例如 abc1234）
git reset --hard abc1234

# 强制推送（⚠️ 谨慎操作）
git push origin feature/stream-chat-ui --force
```

### 手动回滚（如果需要保留部分代码）

#### 1. 恢复备份文件

```bash
# 如果创建了备份
mv app/src/main/java/com/aichat/workbench/feature/chat/ChatMessageList.kt.backup \
   app/src/main/java/com/aichat/workbench/feature/chat/ChatMessageList.kt

mv app/src/main/java/com/aichat/workbench/feature/chat/ChatInputBar.kt.backup \
   app/src/main/java/com/aichat/workbench/feature/chat/ChatInputBar.kt

mv app/src/main/java/com/aichat/workbench/feature/chat/ChatTopBar.kt.backup \
   app/src/main/java/com/aichat/workbench/feature/chat/ChatTopBar.kt
```

#### 2. 恢复 ChatScreen.kt

```bash
# 使用 Git 恢复到 Phase 2B 之前的版本
git checkout <phase2b-commit> -- app/src/main/java/com/aichat/workbench/feature/chat/ChatScreen.kt
```

或手动：打开 `ChatScreen.kt`，取消注释旧代码，删除 Stream 代码。

#### 3. 恢复 ChatViewModel.kt

同样使用 Git 或手动恢复：

```bash
git checkout <phase2b-commit> -- app/src/main/java/com/aichat/workbench/feature/chat/ChatViewModel.kt
```

#### 4. 删除数据同步代码

删除 `DataSyncManager.kt` 和相关调用。

#### 5. 验证和测试

```bash
./gradlew assembleDebug
# 运行应用，测试所有功能
```

## Phase 4 回滚

**情况**: 清理优化阶段发现问题，但代码已被删除

**影响**: 高，旧代码已删除

### 回滚步骤

#### 1. Git 回退

```bash
# 回退到 Phase 3 结束
git log --oneline
git reset --hard <phase3-commit>
```

#### 2. 恢复已删除的文件

如果只是想恢复某些文件：

```bash
# 查看某个文件的历史
git log -- path/to/file.kt

# 恢复特定版本的文件
git checkout <commit> -- path/to/file.kt
```

#### 3. 验证

全面测试应用，确保功能正常。

## 完全回滚到 main

**最后的手段**: 放弃整个 Stream SDK 迁移

### 步骤

#### 1. 保存学习成果

```bash
# 创建存档分支（保留实验结果）
git checkout feature/stream-chat-ui
git branch archive/stream-chat-experiment
git push origin archive/stream-chat-experiment
```

#### 2. 切换到 main

```bash
git checkout main
git pull origin main
```

#### 3. 删除实验分支

```bash
git branch -D feature/stream-chat-ui
git push origin --delete feature/stream-chat-ui
```

#### 4. 清理本地

```bash
./gradlew clean
./gradlew assembleDebug
```

#### 5. 验证

运行应用，确保一切正常，就像从未开始迁移一样。

## 回滚后的数据处理

### Room 数据库

**好消息**: Room 数据库不受影响，所有消息仍然保存。

**验证**:
1. 运行应用
2. 检查现有会话和消息是否完整
3. 尝试创建新会话和发送消息

### 用户设置

所有用户设置（Provider 配置、API Key 等）保存在 DataStore 中，不受影响。

### 迁移期间的测试数据

如果在测试过程中创建了测试数据：

```bash
# 清理测试数据（可选）
adb shell pm clear com.aichat.workbench
```

## 预防性建议

为了减少需要回滚的风险：

### 1. 分支策略

```bash
# 主要分支
main                           # 稳定版本
feature/stream-chat-ui         # 迁移工作

# 检查点分支（每个 Phase 结束创建）
checkpoint/phase1-complete
checkpoint/phase2a-complete
checkpoint/phase2b-complete
checkpoint/phase3-complete
```

### 2. 频繁提交

每完成一个小步骤就提交：
```bash
git add .
git commit -m "feat: 完成 XXX"
```

### 3. 充分测试

每个 Phase 完成后充分测试再继续。

### 4. 增量迁移

不要一次性替换所有组件，逐个替换并验证。

### 5. 保留备份

```bash
# 创建备份分支
git branch backup/before-stream-migration
```

## 最后的话

回滚不是失败，而是明智的决策。

- ✅ **好的回滚**: 及时发现严重问题并止损
- ❌ **不好的回滚**: 遇到小问题就放弃，没有尝试解决

在决定回滚前：
1. 仔细阅读 `06-故障排查.md`
2. 在 Phase 2B 充分验证
3. 咨询有经验的开发者
4. 评估修复成本 vs 回滚成本

祝好运！🍀
