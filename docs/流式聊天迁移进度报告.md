### Phase 2A: 并行开发实验版本

**提交**: `9f53a11` - feat(stream): Phase 2A 完成
**检查点**: `checkpoint/phase2a-complete`

**内容**:

1. ✅ **数据转换层**
   - `MessageConverter.kt` - Domain Message ↔ Stream Message
     - 支持消息角色转换（User/Assistant/System）
     - 支持时间戳转换（Instant ↔ Date）
     - 支持流式消息创建
   - `ConversationConverter.kt` - Domain Conversation ↔ Stream Channel

2. ✅ **数据仓库层**
   - `StreamChatRepository.kt`
     - 管理当前用户状态
     - 消息同步到 Stream Channel
     - 从 Stream Channel 获取消息

3. ✅ **ViewModel 层**
   - `StreamChatViewModel.kt`
     - 桥接 Domain 层和 Stream UI 层
     - 加载会话并转换消息
     - 发送消息（含模拟 AI 响应）
     - UI 状态管理（Loading/Success/Error）

4. ✅ **UI 层**
   - `StreamChatScreen.kt`
     - 基于 Stream Compose UI 的聊天界面
     - 使用 `MessageList` 显示消息
     - 使用 `MessageComposer` 输入消息
     - 使用 `MessageListHeader` 顶部栏
     - 应用 `AiChatStreamTheme` 主题

5. ✅ **依赖注入**
   - 在 `AppModule.kt` 注册：
     - `ChatClient.instance()`
     - `StreamChatRepository`
     - `StreamChatViewModel`

**架构设计**:
```
Room Database (持久化)
       ↓
MessageConverter (转换层)
       ↓
Stream Message (内存)
       ↓
Stream UI Components (展示)
```

- ✅ Koin 依赖注入配置正确

## 🔍 风险与注意事项

### 已识别的风险

1. **Phase 2B 可能失败**（概率：中）
   - Stream SDK 可能不完全适配我们的需求
   - 性能可能不达标
   - **缓解**: 保留完整回滚方案

2. **数据同步复杂性**（概率：高）
   - Room ↔ Stream 双向同步可能有延迟
   - 可能出现数据不一致
   - **缓解**: 使用 Room 作为唯一数据源，Stream 仅展示

3. **学习曲线**（概率：中）
   - 团队需要学习 Stream SDK API
   - 文档可能不完整
   - **缓解**: 已创建详细的实施文档

4. **时间成本**（概率：确定）
   - 预估还需 6-10 天完成
   - 可能遇到未预见的问题
   - **缓解**: 渐进式迁移，每步可回滚

### 退出策略

如果 Phase 2B 失败（总分 < 70）：

```bash
# 1. 回滚到 main
git checkout main

# 2. 保留实验分支供参考
```
