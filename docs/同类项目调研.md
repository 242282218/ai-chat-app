# 同类项目调研

调研日期：2026-06-07

当前结论更新：2026-06-09

## 当前项目定位

当前项目收敛为原生 Android AI 聊天应用，核心只保留：

- BYOK 多 Provider 文本聊天。
- 本地优先会话历史。
- 图片输入和图片生成。
- Provider 配置、模型选择和多模态入口组织。

明确不做近期主线：

- 工具调用、Gateway、网页搜索、代码沙箱。
- Skill、Agent workflow、RAG、长期记忆。
- 语音、TTS、角色卡、本地大模型运行时。

## 落地原则

### 1. 历史数据必须可容错

聊天历史、旧图片结果、坏 JSON、旧枚举和旧消息角色都要按不可信输入处理。旧工具消息只作为历史兼容展示，不再进入新能力入口。

### 2. Provider 配置优先清晰

Provider 设置只表达聊天、视觉和图片能力。模型连接需要清楚展示 Base URL、API Key、默认聊天模型和图片模型，不再出现工具模型或代码模型。

### 3. 图片生成保持独立主路径

图片生成使用 OpenAI-compatible `/v1/images/generations`，记录本地历史，支持复用提示词、保存和分享。失败记录转聊天时使用“图片生成请求”语义，不再伪装为工具调用。

### 4. 不再扩展工具平台

工具、Gateway、搜索、沙箱、Skill、RAG、长期记忆都不进入当前产品主线。当前 Room schema 已删除旧工具、提示词预设和长期记忆存储；历史迁移仅保留从旧版本升级所需的兼容 SQL。

## 当前优先级

### P0：聊天和图片主路径稳定

- 会话列表、消息渲染、图片预览、图片生成历史必须稳定。
- Provider 错误要映射成可理解的恢复建议。
- Android 单测和 lint 保持绿色。

### P1：继续清理历史兼容边界

- 当前 Room schema 不再包含工具、提示词预设和长期记忆表。
- 分批移除不可达运行时、依赖和文档引用。
- 旧版本升级路径继续通过迁移测试覆盖。

### P2：改善体验但不扩大范围

- 可优化多 Provider 配置、模型发现、图片参数和历史筛选。
- 暂不做多模型并行、语音、本地推理、RAG 或 Agent workflow。
