# 全面重构设计

日期：2026-07-01

## 背景

本项目是原生 Android AI 聊天应用，当前技术栈为 Kotlin、Jetpack Compose、Material 3、Room、Koin、OkHttp、kotlinx.serialization 和 Baseline Profile。目标是在保留本地优先、聊天和图片生成定位的前提下，参考 `参考项目/` 中的成熟项目，对架构、同类功能、UI 和工作区进行系统性重构。

已确认采用方案 A：

- 借鉴 `OneClaw` 的本地优先 Clean Architecture、Koin 模块拆分、聊天主屏、会话抽屉、设置列表和 Provider 管理结构。
- 借鉴 `GPT-Mobile` 的多 Provider 配置、设置向导、聊天输入和多模型选择逻辑。
- 参考 `chatgpt-android` 的设计系统组织和多模块边界，但不直接引入 Stream Chat SDK 或 Hilt。

## 成功标准

- 架构层次更清晰：依赖注入、数据库、网络、Repository、Provider 和 Feature 注册拆分为独立模块。
- 同类功能更接近参考项目：Provider 管理、聊天主屏、会话历史、图片生成入口和设置入口有明确边界。
- UI 参考落地：主体验从底栏三页调整为聊天优先体验，历史通过抽屉进入，设置以列表方式承载二级功能。
- 代码语言和逻辑保持一致：继续使用 Kotlin、Compose、Koin、OkHttp、Room 和 kotlinx.serialization，不引入不必要的新技术栈。
- 工作区更干净：无效截图、临时文件和过期文档被识别并整理；新增文档使用中文命名。
- 验证通过：至少通过 `testDebugUnitTest`；涉及 UI、资源或构建配置时通过 `lint assembleDebug`。

## 非目标

- 不引入 OneClaw 的 agent、tool、skill、memory、bridge、Git versioning、QuickJS 或 Google Drive 同步能力。
- 不引入 GPT-Mobile 的 Hilt、Ktor 或多模型并发回答机制，除非后续单独确认。
- 不引入 chatgpt-android 的 Stream Chat SDK、AppStartup、WorkManager 聊天后台任务或 Hilt 架构。
- 不重置 Room 数据库，不丢弃现有用户数据。
- 不自动创建 Git commit、tag、release 或发布 APK。

## 架构设计

### 目录目标

当前仍保留单 Android app 模块，先在包内重构边界，避免一次性拆 Gradle 多模块带来过大迁移风险。

目标包结构：

```text
com.aichat.workbench
├── app
│   ├── AiChatApplication.kt
│   ├── AppDispatchers.kt
│   └── di
│       ├── AppModule.kt
│       ├── DatabaseModule.kt
│       ├── FeatureModule.kt
│       ├── NetworkModule.kt
│       ├── ProviderModule.kt
│       └── RepositoryModule.kt
├── data
├── domain
├── feature
├── navigation
├── provider
└── ui
```

### DI 拆分

参考 OneClaw 的 `di/` 组织，把当前大 `AppModule.kt` 拆为：

- `AppModule.kt`：Clock、dispatchers、application scope、基础配置。
- `DatabaseModule.kt`：Room database、DAO 暴露、迁移注册。
- `NetworkModule.kt`：OkHttpClient、SSE/JSON/long-running client。
- `RepositoryModule.kt`：Room repository、SecretStore、ImageStorage、DataStore preferences。
- `ProviderModule.kt`：ProviderRegistry、ChatProvider、ImageGenerationProvider、model discovery、connection tester。
- `FeatureModule.kt`：UseCase、feature controller、ViewModel。

拆分后应保持 Koin 注册行为不变，现有测试不需要知道模块内部拆分。

### 数据层

Room schema version 仍为 18。迁移策略：

- 保留 `AiChatDatabase` 作为 Room database 定义。
- 将迁移常量和大段 SQL 迁移拆到 `data/local/migration/` 下，减少 database 文件职责。
- 保留现有 schema JSON 和迁移测试覆盖，不做 destructive migration。
- Entity 不泄漏到 domain/feature，继续通过 mapper 转换。

### Provider 层

参考 OneClaw 的 adapter/factory 思路，但保留本项目已有 provider 能力：

- `ProviderRegistry` 保留统一 provider 描述和能力判断。
- OpenAI Responses、OpenAI-compatible Chat Completions、图片生成协议继续使用现有 OkHttp + kotlinx.serialization 实现。
- 整理协议代码位置，使 request 构建、SSE 解析、错误映射、连接测试边界清晰。
- 不改变用户已有 Provider 配置表结构，除非后续必须新增字段并补迁移。

## 功能设计

### 聊天

主屏改为聊天优先：

- App 启动后进入聊天主屏。
- 顶栏提供会话抽屉入口、当前会话标题或新对话标题、Provider/设置入口。
- 历史会话通过左侧抽屉查看，参考 OneClaw 的 Session Drawer。
- 新对话、选择会话、删除会话、清空上下文、搜索消息、停止生成、重试和图片输入保留。
- 当前 `ConversationManager`、`GenerationController`、`ConversationContextBuilder` 继续承担核心编排职责，但按职责拆分文件和依赖。

### Provider 和设置

设置从底栏页调整为二级列表：

- 设置列表包含：模型服务、图片生成、数据与隐私、外观、关于。
- 模型服务入口沿用现有 ProviderSettings 功能，视觉参考 OneClaw Provider list 和 GPT-Mobile platform setting。
- Provider 表单保持 OpenAI、OpenAI-compatible、New API、Sub2 API、Custom、OpenRouter、Ollama 等现有类型。
- 图片生成模型选择仍通过 `ModelRolePreference` 中的 Image role 管理。

### 图片生成

图片生成保留为独立功能，但不再作为底栏一级常驻页：

- 从设置列表、聊天输入附加入口或聊天主屏快捷入口进入。
- 表单、参数、连接测试、作品库和发送到聊天能力保留。
- UI 参考当前页面和 GPT-Mobile 的设置面板，减少过度大卡片，保持移动端输入效率。

## UI 设计

### 参考来源

- OneClaw：聊天主屏、会话抽屉、设置列表、Provider 列表的轻量 Material 3 风格。
- GPT-Mobile：聊天列表、FAB、Provider 设置项、参数弹窗和多 Provider 选择体验。
- 本项目现有 UI：中文文案、本地优先提示、绿色强调色、图片生成表单。

### 信息架构

第一屏为聊天，不再以底栏承载“对话 / 图片 / 模型”三页。

```text
聊天主屏
├── 左抽屉：会话历史、新建会话
├── 顶栏：会话标题、Provider 状态、设置入口
├── 内容：消息列表 / 空状态
└── 底部：输入栏、图片附件、发送/停止

设置
├── 模型服务
├── 图片生成
├── 数据与隐私
├── 外观
└── 关于
```

### 视觉原则

- 保留 Material 3，避免引入额外 UI 框架。
- 减少过大的圆角和重装饰，让聊天列表更接近 OneClaw 的紧凑可读风格。
- 按移动端扫视优化信息密度，避免卡片套卡片。
- 中文文案保持直接：优先显示当前状态和下一步动作。

## 错误处理

- 保留现有 Provider 错误恢复、HTTP 错误解析和连接测试能力。
- 对用户可处理的错误给出明确动作，例如“配置模型”“检查 API Key”“重试”。
- 内部 repository error 继续带上下文，不吞错误。
- 不为不存在的场景新增复杂错误分支。

## 工作区整理

- 识别 `artifacts/` 中当前截图用途：保留作为 UI 基线或移动到文档引用位置；误采集截图不纳入最终文档。
- 过期迁移说明、阶段文档不在本次直接删除；仅在确认无引用、无当前价值时整理到归档说明。
- 新增 docs 文件使用中文命名。
- 不修改 `.gitignore`、release 规则或 CI，除非重构验证明确需要。

## 分阶段实施

### 阶段 1：DI 和架构拆分

- 创建 `app/di` 包并拆分 Koin modules。
- 更新 `AiChatApplication` 使用模块列表。
- 保持行为不变，跑 `testDebugUnitTest`。

### 阶段 2：数据库迁移文件整理

- 将 migrations 拆出 `AiChatDatabase`。
- 保持 schema version 18 和 schema JSON 不变。
- 跑数据库测试和迁移测试。

### 阶段 3：Provider 层整理

- 整理 Provider module、protocol、connection tester 和 model discovery 注册。
- 保留现有 provider 类型和兼容逻辑。
- 跑 provider 相关单测。

### 阶段 4：导航和 UI 重构

- 用聊天主屏替换底栏三页信息架构。
- 实现会话抽屉、设置列表、图片生成入口调整。
- 保留现有聊天、图片生成和 Provider 配置能力。
- 跑 UI/Compose 相关单测；必要时用截图验证关键页面。

### 阶段 5：清理和全量验证

- 整理临时截图和文档。
- 跑 `testDebugUnitTest lint assembleDebug --no-daemon --stacktrace`。
- 汇总改动、风险和未覆盖点。

## 测试计划

- 基线：已确认当前 `testDebugUnitTest` 通过。
- 阶段 1：`.\gradlew.bat testDebugUnitTest --no-daemon --stacktrace`
- 阶段 2：`.\gradlew.bat :app:testDebugUnitTest --tests "*AiChatDatabaseTest" --tests "*AiChatMigrationTest" --no-daemon --stacktrace`
- 阶段 3：Provider 相关 testDebugUnitTest 子集。
- 阶段 4：相关 ViewModel 和 UI 逻辑单测；截图检查聊天、抽屉、设置、图片生成。
- 最终：`.\gradlew.bat testDebugUnitTest lint assembleDebug --no-daemon --stacktrace`

## 风险与取舍

- 不直接拆 Gradle 多模块：牺牲模块级编译隔离，换取迁移安全和较低回归风险。
- 不引入新 DI/网络栈：牺牲与 GPT-Mobile 完全一致，换取与本项目现状一致和更少依赖震荡。
- UI 改为聊天主屏：用户路径更接近 AI 聊天应用，但需要调整现有底栏导航和截图基线。
- 数据库只整理文件不改 schema：无法一次性清理所有历史迁移复杂度，但能保护用户数据。
